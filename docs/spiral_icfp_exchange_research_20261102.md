# 2026-11-02｜v0.2 新增設計競爭：全域等長概念詞典、自然語言多說法

U 在本輪強調：**螺旋語不是已凍結的一種形式**；想要什麼功能可增加詞，或用空碼位，只要詞界及語義沒有衝突；有多種表達且相容是優勢，像自然語言但保留層次骨架。例：數學概念（加、若干運算元、句號）、數學實體可作另一數學實體輸入、描述詞「後面有兩個句號」是一個詞而非兩次終止符、問句／「啥意思（要求更多示例）」、引用學生原話與假想學生示範、說話者可以存在一到三層。這些 U 原始概念不能歸功於 A 的後續程式設計。

新增**兩條並列實驗線**：(A) 分層可獨立詞長／擴階；(B) **一個概念可直接分配一個詞碼、所有詞全域等長 N、需擴充時一起升級 N**。B 線同義詞可分配不同碼，獲得機器上精確區分的表達自由；但占用更多碼位、全域升級增成本，且**過於方便直接給新 ID，可能妨礙詞根與可組合詞義形成**。不要把 B 線說成已取代 A 線，也不直接宣稱機器語言優於自然語言。詳見 `/AI研究記憶/螺旋語與MLP.md` 第 3 節。

**關鍵驗證門檻**：固定 N 僅確保詞界，不自動確保尾 `0`／`00`／`000` 的層級無重疊；需明確 `(k,n,offset)` 上下文或精確尾零約束／保留碼。全域擴容同樣要版本握手與新舊碼映射，不能說改 N 後舊流自然仍可讀。比較時加入「同義詞直接編號 vs 詞根組合」消融測試，觀察新概念學習成本、翻譯／引用、總 bits 和長期詞典生長。所有語法仍屬 U 提案／A 待測分析，未做新的 ICFP 移植或學生 B 後續實驗。

**[更新]** 在原「雙向吸收」框架加入全域等長概念碼與構詞壓縮的競爭路線；**[取代]** 只研究某一套固定詞長設計的假定；**[原因]** U 提出概念詞、同義詞與詞根難形成這組新的成本取捨；**[狀態]** 方案待試驗，已建專題記憶。

# 螺旋語 × ICFP 2020：雙向吸收與持續演化研究路線

版本：研究提案 v0.2｜2026-11-02｜狀態：待設計／待實測；不是新語法定案

## 0. 這份報告的用途與來源

**使用者 U 的原始研究方向**：不要一直把「尚未固定的螺旋語」與「2020 年競賽已完成的語言」做靜態優劣比較。螺旋語固定部分很少，許多具體語法、詞位與操作只是暫定版本。更適合的研究是：把 ICFP 2020 有效的機制直接吸收進螺旋語，檢查吸收後是否依然簡潔、好用、易於修改；反過來，也讓 ICFP 2020 的語言吸收螺旋語的階層、詞典演化和版本等功能，觀察成本與後續可修改性。往後設計螺旋語新語法，可直接把 ICFP 2020 當作成熟機制庫，而不是每次都從零發明或勉強以舊草案迎戰。

**A（AI）整理／待驗證提案**：下列吸收清單、測試程序及量化指標是研究設計建議，不能回填為 U 已定案的編碼、原論文已具備的能力或已通過的實驗成果。

資料脈絡：本資料夾的《實驗紀錄.md》記錄 2026-11-01～02 教師 A／學生 B 的純 01 教學；《螺旋語MLP_教師交接報告_20261101.md》提供實作與教學交接。B 的實驗已隨臨時視窗掉線封存；B 使用具名函式的成果及教師曾反覆修改 NAME 詞階的錯誤，均屬歷史證據，不能拿新語法改寫舊資料。

## 2026-11-02｜補充：兩語言有強共通性，區分真正的開發生命週期

U 補充：兩者如都在發展，許多功能很容易互相參考；2020 年競賽語言更固定、偏程式語言，後續更新可能慢且未必相容。A 註：這是**對設計性格與未來修改成本的推論**，不是已統計到 ICFP 發版頻率的觀察。ICFP 2020 是特定競賽規格，不能把未繼續演進誤寫成「持續維護卻更新慢」；其函式組合可擴充，一般函式新增和原生 Modulation 首碼擴充的成本不同。

比較方法應增加三種固定情境：① 核心語法凍結只允許用既有組合子與函式；② 雙方都允許新增詞義／函式與語法糖；③ 雙方都允許變更核心詞碼、字典與版本，但必須保證規定範圍內的向後相容。逐輪評估功能可吸收程度、舊資料能否讀、翻譯工作量、同步費用與後續再次修改的代價。要以**同樣開發權限**測試，不把 ICFP 封死再宣稱 SLE 更靈活。此項為 U 研究方向與 A 試驗建議，尚未實測。


## 1. 方法改變：由固定對照轉為雙向吸收

舊問題：「在一套固定編碼下，螺旋語比 ICFP 2020 少幾個詞？」這可用於局部基準，卻不足以評價可演化語言。新問題：「兩套系統接受同樣的新功能、使用一段時間、再連續修改需求之後，各自付出了什麼代價，還保留了多少原本的優點？」

分兩條路線並行：

- **SLE ← ICFP**：可將 ICFP 2020 的函式應用、配對與串列、遞迴組合、具名引用、互動狀態與自描述資料長度吸收到螺旋語的語義及工具中；優先考慮**用原有階層與新增詞**自然表達，不必原封搬進 `ap ap` 或 `cons` 的表面語法。吸收後仍須能增加詞、擴階、換版本並保留可讀／可解析的舊資料。
- **ICFP ← SLE**：在 ICFP 2020 既有函式應用與資料結構基礎上，加入可用既有訊息宣告的高低層語義分類、詞表擴容、版本重映射、可變參數概念運算、描述／引用／修改等需求。可以用其既有組合子、列表、函式與解譯器擴展來實作；不要預設對方一定做不到，也不要把「能包一層螺旋語解譯器」直接當作「原生吸收已完成」。

**成功標準不是誰模仿得最像**，而是在功能相同、語義明確、可往後擴展時，新增的概念和例外是否少，是否能做局部修改，並且成本可接受。若兩邊都吸收得很好，也是一項有效結果；共同機制可能比品牌差異更重要。

## 2. 哪些應保留、哪些不能冒充既定標準

目前值得保留並檢驗的是：階層性描述與跨層語義、由共識決定的 `k/n/offset` 詞界、可擴階的詞域、以舊規則宣告新規則的版本／詞典更新，以及用實際工作需求推動語言生長。這是**核心研究方向與解析條件**，不表示每種數學運算、每個詞位、句號、數字編碼或函式語法都已被固定。

例如以下是 U 在 2026-11-02 明確提出的**候選語義骨架**，不是已分配好位元、通過測試的新標準：

- 舊：`二層：數學 → 降層／句號；一層：普通算式`。
- 擴充：`二層：數學 → 命名 → 降層／句號；一層：新算符 → 構成算符 → 句號`。
- 普通：`二層：數學 → 普通 → 降層／句號；一層：已知算符 → 資料／實體 → 句號`。
- 數學描述可回傳數學實體、再被其他數學描述當作輸入。像「後面有兩個句號」應視為**可新增的一個描述詞**，不是在比特流中重複兩個句號；其位置、作用域與巢狀計數需要測試。

**必要限制**：新增詞沒有碼位衝突，不等於語義或結構必然唯一；還須判定當前層、詞長、作用域、結束條件和解析上下文。未事先同步 `n/k` 或版本時，不能把事後能猜出來冒充保證唯一解碼。要更換詞長、詞階、詞義，應先用舊版可讀的宣告建立新上下文，不可靜默改規則。

## 3. ICFP 2020 可優先吸收的具體機制

需區分**外星程式語言／圖形教材**與**二進位 Modulation 序列化**，不能拿其中一個的成本聲稱整套語言的成本。

| 2020 機制 | 已有功能 | 螺旋語可考慮的吸收方向（A 提案，未定案） |
| --- | --- | --- |
| `ap` 函式應用 | 以固定元數建立遞迴表達式 | 「呼叫／應用」概念詞，或整個數學實體作為參數；是否保留前綴語法以實驗為準 |
| `cons`、`nil`、列表簡寫 | 配對、空串列、任意長串列與巢狀資料 | 「配對」「空」「列表」等概念，可配合長度或結束詞；測插入、刪除、巢狀詞界 |
| S/B/C/I 等組合子 | 藉少量基礎規則組合函式 | 可執行函式定義／組合，不限於兩步 AND→CUT；不必強制採用同一組合子表面編碼 |
| 具名定義與引用 | 先定義後重複使用 | 二層「命名」模式與一層算符名稱等候選；新名稱要能明確引用、更新和避免碰撞 |
| `interact`、狀態式互動 | 使用函式處理互動狀態／資料交換 | 協議狀態與詞典版本的關係；辨別「執行狀態」與「語言版本」 |
| Modulation | 用前綴標記及遞迴配對結構唯一地讀出資料邊界 | 可選的自描述長度／資料型別機制，研究與共享 `k/n` 時的成本取捨 |

## 4. 雙向吸收的最低可重現測試

**階段 A｜功能對齊**：先制定兩邊都要通過的相同任務及預期語義：五項與一百項平坦求和、`(1+2)×(3+4)` 巢狀、任意層串列、函式命名與重用、跨資料型別的描述／保留原式與求值，以及資料往返的唯一解析。若有實驗尚不支援某項，標為未完成，不能靠示意句當 PASS。

**階段 B｜增量修改**：在已存在的語法和程式上，依序增加中間的幾個運算元、把普通數字換成完整數學實體、加入新函式、重新命名、改運算符意義、升級詞長及版本並仍讀舊資料。量每一步是否只修改局部，是否破壞既有解碼器或語義。

**階段 C｜使用者／智能體實測**：兩邊都做完整教師示例和可執行驗證器，讓同等能力的受試者使用；評估「主動產生新詞／新問法」「交換函式」「遇到未知版本的恢復」等實際能力。區分 AI、人類、機械評分，嚴格記錄實收訊息，不能把計畫中的題包算作訓練成果。

**階段 D｜持續成長**：每次新增功能後再繼續改需求，而不是只跑一次 baseline。觀察規則數、例外分支、詞典同步與版本轉換費用是否成長過快；檢查大規模後仍正確、可擴展，不追求只在小題庫中一時較快。

指標至少包含：新增與總傳輸 bits、詞表／教材 bits、平均執行與解析步數、記憶體／解譯器成本、遷移舊資料費用、受影響舊規則／舊程式數、未見過任務正確率、回復錯誤所需互動。若整合指標，不同成本需要正規化，不可把 bits、CPU 時間和主觀「醜」直接相加。語法美觀可用可讀結構、特殊情況數與需要額外重寫的地方來輔助評價，但不可僅由 AI 審美決勝。

**公平性**：先定好相同的功能、任務及演化事件，允許雙方使用本來擅長的構件；同時保留固定語法／不擴展的基準組，以免「誰加了更多專用詞」直接勝出。要分別報告一次性學習成本和重複使用後的攤銷成本。

## 5. 新語法設計與發表流程（2026 實驗的重要教訓）

1. 先問「現有詞或功能組合可否自然表達？」同時直接參考 ICFP 2020 的成熟解法；無須為了不相似而拒絕吸收。
2. 若要加詞，先判斷屬二層描述／模式詞、一層可執行算符、資料結構詞，還是需另外的作用域／遞迴規則；確認每個類別的上下文及詞界。
3. 離線寫出完整定義句、呼叫句、解析器狀態與反例；驗證新舊版不會在未宣告下混讀，並測試巢狀與任意數量輸入。
4. 以程式作正反測試：唯一切詞、求值、往返、資料插入、未知詞、版本切換、舊資料可讀、故意衝突與錯誤復原。
5. 確認可用後再發給學生；上場後若需修正，使用學生能讀懂的版本宣告及明確新詞教學，不因臨時想法反覆偷換教師規則。
6. 記錄 U 原始構想、A 推導、歷史已測 T、未測候選各自來源。研究重心是**能用、願意用、用久仍能改**，不是在紙上預先定死所有語法。

## 6. 已知漏洞與結論狀態

- 2026-11-02 的 B 實驗證實有限互動式教學與受提示的命名／呼叫嘗試，**未**驗證新「數學實體套數學實體」編碼、ICFP 功能吸收或雙向移植。
- 當時教師誤把降層後的 NAME 稱作「二層名字」，其後又為接受學生輸出臨時放寬尾碼。這一歷史錯誤是「先驗證層級／版本」的回歸案例；不可用新設計塗改 B 的原始位元。
- 2020 的函式組合、串列與前綴資料格式已實際存在；我們不應把它的表達能力貶成只能二元加法，也不應將螺旋語的未定案能力當已實裝。

**[取代]** 把當前某一版螺旋語與 2020 固定系統反覆靜態比較，或為了維持兩者差異而拒絕借鑑。
