# Pro：有位置的升階通知 UR1

日期：2026-11-13（Asia/Taipei）。設計與整合：**ChatGPT Pro**。通知初稿基底為 Codex P034 `5e6a25c8bb809f8130b60c257280aa72225a5f89`；發布時已讀取並整合 P035 `a309f2fc3e23255327fcab35745c27012d15ed4f`。本文件是新候選 profile；沒有改寫歷史 SLE、P030–P035 的資料、parser 或模型。P035 的訓練與原始稽核歸 Codex／受指派 agent，本次 Pro 沒有重跑它們。

U＝使用者構想；F＝指定版本的原始碼／資料；T＝實際執行結果；A＝Pro 設計或尚未驗證的推論。使用者提出「各位置可通知升階、通知可連續三份、答案只重複相關通知、最高與次高碼作通知／句號」記為 U。結構地址、三份代表同一次事件、以下 UR1 封裝與確認規則記為 A。附帶 codec 的測試只驗證編碼和狀態轉移，不是神經網路學習結果。

## 1. 選定格式：位置放前面，答案只確認局部

建議首版固定使用：

```text
題目：通知開頭｜位置地址｜新寬度 UP｜新寬度 UP｜新寬度 UP｜新寬度 END
答案：位置地址｜新寬度 UP｜外部 STOP
```

分隔線、中文名稱與空白只是閱讀標註。學生輸入仍只有 0/1；輸出只有 0/1 與既有外部 STOP。地址也是真的輸入位元，不能把路徑名稱、解析結果、目標寬度或 notice flag 額外餵給學生。

前綴回答「哪裡升階」，尾端 END 確認通知完整結束。答案重複地址和一份 UP，避免把整條數學題當作抄寫題。若只要求回答 UP，同一寬度下所有位置的正解會完全相同，無法檢查模型是否注意到位置。即使地址也答對，仍須另外檢查它是否真的把新寬度用於正確分支。

地址指向穩定的語法樹節點，例如算符、第一資料域、第二資料域、某分支下的算符。它不是「第幾個 bit」；前方詞寬變長後，節點 ID 和地址含義仍保留。若兩個欄位共用同一個寬度狀態，兩者必須使用同一條 canonical 地址，不能各加一次。本版只支援真正的樹，不支援兩個不同路徑 alias 到同一 Node 的共享 DAG 或循環；接收器初始化會拒絕這種拓撲。本次 fixture 用獨立資料域展示定位能力，不宣稱目前所有歷史 parser 已有獨立的 A/B 寬度。

## 2. UP 和 END 的精確規則

已知資訊寬度 n 和層尾長 k，數值詞為 `binary(value, n) + 0^k`。採用使用者提議的尾兩碼：

\[
\operatorname{UP}(n,k)=1^n0^k,\qquad
\operatorname{END}(n,k)=1^{n-1}0^{k+1}.
\]

| 資訊寬 n，k=1 | UP：最高 ID | END：次高 ID | 控制／算符域可分配的普通 ID 數 |
|---|---|---|---:|
| 1 | `10` | `00` | 0 |
| 2 | `110` | `100` | 2 |
| 3 | `1110` | `1100` | 6 |
| 4 | `11110` | `11100` | 14 |
| 5 | `111110` | `111100` | 30 |

`111100` 在 n=5、k=1 時有五個資訊位 `11110` 加一個層尾 `0`，不是看到兩個尾零就判成 k=2。k 來自地址所指分支的文法。地址的深度也不等於 k。

**保留碼依欄位角色生效。** 普通數值域仍可使用全部 `2^n` 個數值；n=5、k=1 的資料 31 仍是 `111110`，資料 30 仍是 `111100`。地址的 count／ID 也是普通數字，可使用完整值域。只在通知欄或控制／算符角色將尾兩碼解釋為特殊符號。不能掃描整段 raw bits，把任何連續三個 `111110` 都當成通知：合法資料可以恰好出現相同片段。

控制／算符域的已分配最高 ID h 必須滿足 `h ≤ 2^n - 3`。h 是相應樹節點裡的「歷來最高分配 ID」，不能按當前剩餘算符數目重新計算。升寬保留既有 ID；本次只改 n，不新增或重排既有 ID。

## 3. 三份通知代表一次升階

本方案選擇用**目標新寬度**寫 UP。例如原 n=4，要升至 n=5，通知是 `111110` 三份，END 是 `111100`。看到 UP 的資訊位數就能在明確通知欄中讀出目標 m；不用先以新寬度解析地址。

這裡的「升階」是某節點 `n → n+1`。被定位的節點可以在任一層，該節點的 k 維持不變。k 自身改變、重新分配語義或更換地址格式不混入這種通知。

| 收到的目標 m | 確認整個 frame 合法後的處理 |
|---|---|
| m = 目前 n + 1 | 該位置升寬一次，設定 n=m |
| m = 目前 n | 重播確認，n 不變 |
| m < 目前 n | 舊通知，拒絕且狀態不變 |
| m > 目前 n + 1 | 首版不接受跳階，拒絕且狀態不變 |
| 三份不同、END 錯、地址不存在、內容截斷 | 拒絕且任何節點均不變 |

三份 UP 必須完全相同；全部讀完並驗證 END 後才提交一次。重複三份是教學冗餘，不是累加三次，也沒有多數決修復功能。地址若改成另一個合法地址，frame 仍可能合法；這套格式沒有承諾偵測所有傳輸錯位元，回覆還須和原題的完整地址／目標配對。需要連升三階時，使用三個完整通知，例如 4→5、5→6、6→7；同一通知重播多次都不會自動繼續升寬。

這套重播規則只處理不下降的同一條詞彙演進線。它不是跨分叉版本或斷線併發的完整同步協議。語言配置需要保留版本來源；不能用 n 相同就宣稱兩個版本語義相同。

## 4. UR1 的完整純位元封裝

為了讓前後界線明確，首版新增專用控制 frame。固定控制地址寬 c=3，控制開頭為：

```text
001 11100
```

`001` 是 UR1 的外層控制標記；`11100 = UP(3,2)` 是根控制角色的通知碼。UR1 中此標記只界定外層，**不宣告整個 payload 最多只有兩層**。目標詞的 k 由地址所指節點決定，因此可以通知 k=1、2、3 的不同節點。這是新增封裝的明文規則，不把它冒稱為既有通用 parser 已支援的語法。

普通一層題以既有 `01` 起頭；在 UR1 控制域，根的 UP 留給通知。若未來加入其他多層題，必須遵守這個根控制域的保留規則。舊 profile 的多層 raw bits 不能與 UR1 無標記混用。

地址包含「元件數 d」和 d 個穩定子節點 ID，各用 `word(value, c=3, k=1)` 編碼。這個 count 使多層路徑的終點明確，不必重複整條數學題，也不用另加特殊地址結束符。所有地址位元按已知控制寬 c 解析；只有後面的目標通知區使用新寬度 m。

下列是本次有界 fixture 的位置表，ID 是 Pro 新分配的例子，不是既有樹 ID 的考古結論。`[5]` 是示範分支，`[5,5]` 是其子分支。

| 位置 | 穩定地址 | 完整地址位元，含 count | 本次示範升寬 | UP / END |
|---|---|---|---|---|
| 題型的算符域 | `[0]` | `0010 0000` | n4→5，k1 | `111110` / `111100` |
| 第一資料域 | `[1]` | `0010 0010` | n4→5，k1 | `111110` / `111100` |
| 第二資料域 | `[2]` | `0010 0100` | n4→5，k1 | `111110` / `111100` |
| 題目類別域 | `[3]` | `0010 0110` | n3→4，k2 | `111100` / `111000` |
| 版本值域 | `[4]` | `0010 1000` | n3→4，k3 | `1111000` / `1110000` |
| 示範分支的算符域 | `[5,0]` | `0100 1010 0000` | n4→5，k1 | `111110` / `111100` |
| 示範分支的第一資料域 | `[5,1]` | `0100 1010 0010` | n4→5，k1 | `111110` / `111100` |
| 更深分支的算符域 | `[5,5,0]` | `0110 1010 1010 0000` | n4→5，k1 | `111110` / `111100` |

「版本值域升寬」僅表示存放版本值的詞可以變長；它不會自動換版本、搬移地址或啟用未教過的語義。

### 算符 n4→5 的完整例子

```text
Q = 001 | 11100 | 0010 0000 | 111110 111110 111110 | 111100
A =             0010 0000 | 111110 | STOP
```

真正送入學生的 Q 是 40 bits：

```text
0011110000100000111110111110111110111100
```

答案是 14 bits，之後由學生輸出外部 STOP：

```text
00100000111110
```

換成第二資料域時，通知區和 END 完全相同，只把地址從 `0010 0000` 改成 `0010 0100`；答案也必須跟著換地址。這是最直接的位置反例。更深分支則增加必要的路徑元件，不抄算式與資料值。

### 首版邊界與成本

固定 c=3 的 count 和各 ID 都只能表示 0…7；本次 fixture 有八個可通知位置，測例深度最高 3。空地址／根自身升寬、地址寬 c 的成長、任意新樹節點與跨版本 root replay 尚未實作。超出容量前須先凍結、實作並驗收下方控制根升寬候選，保留穩定 ID 與舊 header 的辨識能力。**這個有界 codec 沒有完成整個語言的無限擴張。**

設地址深度 d、目標資訊寬 m、層尾 k，首版實際長度為：

\[
|Q|=8+4(d+1)+4(m+k),\quad |A|=4(d+1)+(m+k).
\]

| 例子，m5/k1 | Q bits | A bits | Q+A 的最大可見 prefix | 至少生成步數，含 STOP |
|---|---:|---:|---:|---:|
| `[0]` | 40 | 14 | 54 | 15 |
| `[5,0]` | 44 | 18 | 62 | 19 |
| `[5,5,0]` | 48 | 22 | 70 | 23 |

既有 P034 的 L16 放不下；只把 L 調大也不夠，[P030 Model.generate()](../../experiments/spiral_neural/20261112_p024_p030/src/p030_binary_continual.py)及[P034 attention 的 generate()](../../experiments/spiral_neural/20261112_p034/attention_model.py)都有 8 步上限。新實驗必須按其完整 manifest 預算設定 context 和 generation cap，並計入位置參數、更多 target 更新、MAC、記憶體與延遲。本文的「只回覆局部」是降低回覆內容負擔，沒有宣稱整個通知輸入比每道普通數學題更短。以上長度只適用表內配置，不是所有未來升階的固定上限。

### 控制根自己的升階：後續候選 A，未實作

為涵蓋最外層位置，可保留 count=0 的空地址給「控制根／地址寬 c」本身。當前 UR1 程式明確拒絕此地址；以下是後續要凍結的新能力，沒有混入已通過的測試數。

把通知 header 使用的舊寬叫 h，接收器目前控制寬叫 c，目標新寬叫 m。header 和空地址仍用 h；根目標 UP／END 用 m、k_root=2。必須滿足 `m=h+1`。新升階要求 `h=c, m=c+1`；重播要求 `h=c-1, m=c`，並且匹配接收器已確認的該次根轉移。其餘拒絕，避免拿已知舊 header 搭配任意新目標跳過正確銜接。

例如控制根 3→4：

```text
Q = 001 | 11100 | 0000 | 111100 111100 111100 | 111000
A =              0000 | 111100 | STOP
```

Q 為 36 bits，A 為 10 bits。完整驗證後才把 c 設為 4；下一則新通知的 header 變為 `001111100`，地址各詞變成四資訊位加一尾零。既有 child ID 保留，舊數值詞前補 0。根自己的 highwater／已確認 profile 歷史留在根節點的持久狀態內。

重播時仍按原 header 的 h 讀原 count 位元，答案原樣複製該 count，不能用目前 c 重新編碼。控制 header 的全 1 通知詞可以在這個專用欄位提供 h；接收器只接受已確認的控制 profile，不把任意自稱的 h 直接寫入現況。這樣可以延伸地址容量，沒有先知道新 c 才能定位根的循環依賴。實際根成長、舊 header 保留、跨題神經學習與成本仍須另行實作測試；有限 fixture 的通過不代表這一段已完成。

## 5. 舊碼的遷移界線

歷史一層示例與 P030 類型配置使用 `100` 表示 Zero、`110` 表示 END；直接套用新規則會把它們改義。UR1 必須另立 profile 與教材版本，保留歷史結果。

需要同時容納 Echo、Neg、Zero 和兩個控制碼時，最小算符資訊寬是 n=3：

| 角色 | 穩定 ID | 新 profile，n3/k1 |
|---|---:|---|
| Echo | 0 | `0000` |
| Neg | 1 | `0010` |
| Zero | 2 | `0100` |
| END | 6 | `1100` |
| UP | 7 | `1110` |

普通 ID 0、1、2 保留，控制碼位置依新寬度計算。只教 Echo、Neg 可由算符 n=2 開始；若啟用雙保留碼，算符 n=1 沒有普通槽位。資料域沒有這個兩槽限制。這不是要求所有資料一開始都用三位元。

## 6. 怎樣教，才知道通知真的有用

建議把通知放進一個短的教學連接：已會的舊格式題 → 該位置通知與局部確認 → 同語義、正確新格式的題。後題保留普通算符的語義 ID 和原數值，先只改指定位置的寬度。不要只用 Echo；Neg 或其他已會的非恆等任務可以檢查學生是否只照抄輸入。若有意再測舊格式，須明示為另一個版本的評估，不能無標記混入當前新 profile。

三份 UP 是一題裡的重複，不等於三次獨立教學。重複多少輪可以另作課程變因；學習效果、所需輪數和是否優於一份通知目前信心中低，沒有實測答案。

| 要分辨的能力 | 最小檢查 | 不能據此推出的結論 |
|---|---|---|
| 知道這是一則通知 | 普通數字 30/31、相近片段與完整通知都出現，分開計錯誤 | 看見長串 1 就一定能升階 |
| 回覆正確位置地址 | 同樣 UP 交換 `[0]`、`[1]`、`[2]` 及分支地址，答案需隨位置改變 | 已把新詞寬用於正確語義分支；局部摘錄本身可以通過這一項 |
| 在升階後真正使用 | 通知後測指定分支的新格式、未指定分支保持原寬度；另測新值與舊語義保留 | 已有無限位寬、任意算符或跨所有分支的泛化 |

最小因果比較應在相同初始模型、物理容量、後續新格式數學課程與停止條件下，比較「正確位置通知」和「沒有有效位置通知的等預算控制」。錯位置通知可作補充干預，觀察錯誤是否跟著位置走；不要把它當成無害的普通複習。重複一份與三份的成本另算，不能只用相同題數冒稱等訓練量。正式開跑前還需凍結 manifest、seed、target 更新上限和評估分割；本次沒有執行這個學習比較。

第一個小比較可只選一個已會算符和一次資料域升寬。從同一完整 checkpoint 與同一物理擴容結果分成兩支：一支訓練 UR1 確認，另一支用同樣 target 更新預算學普通新格式例題；然後接完全相同的新階教材。分別計通知確認、被指定／未指定分支的普通題正確率、達標所需後續更新與舊能力保留。測值同時包括舊範圍換新碼，以及必須用新增高位的值，避免只測補零；測驗答案不回流訓練。通知後立即測一次可作診斷，但不要求零樣本成功才承認後續學習收益。等 target 更新仍不必然等 MAC，需另報實際成本。

目前學生每題重算隱狀態。跨題影響可來自訓練後的權重，不會因 parser 已更新而自動出現在學生腦中。若只生成通知回覆、不更新權重，下一題又未保留通知，就沒有把這次通知帶到下一題的機制；這可作實作負對照。若另外引入跨題記憶或遞迴狀態，需另記架構變因。教師／oracle 可以用樹來產生題目和評分；學生看不到樹、分支標籤或手算答案。

[原因] Codex P035 已完成兩種輸入 codec × Fixed/Growing × 三 seed；已教 144/144，未教運算元 val+test 5/48，配對成長交互作用 0、−1、0。兩側共用答案文法，沒有比較完整系統的最短原生輸出。運算元 4/6 曾在 Neg 教師答案出現，因此不能叫全角色未見。

[狀態] 對固定報告所述的本批結果與完成狀態信心高；不外推其他架構、更大域或通知教學效果。

P035 只改算符位寬時，原 Echo 89/96、新碼入口 0/96、該階末 84/96；同一舊 raw 的擴網 logit 在該事件仍保持。這使 UR1 的問題更具體：通知與前後同語義示例能否降低**新表示的恢復成本**？它沒有證明「缺通知造成失敗」。後續應沿用按題配對的保留／失去／新答對帳，並按輸入、回覆與普通題分別記錄地址、UP 和數值的曝光，避免局部回覆或角色間曝光混淆。P035 最大 L13 也放不下本方案；不把既有小網路的參數數目沿用到更大 context 的通知實驗。

語言 n 的增加與網路增加神經元、層數或 context 容量是不同操作。UP 宣告詞寬，不預先規定要加多少參數。若搭配物理擴網，成長瞬間保留舊權重和 Adam 狀態；後續可正常共同學習。通知答對、擴網保持舊函數、升階後數學進步須分別記錄。
