# P031｜多類數學題庫與重新編碼對照：螺旋語、位值對齊、數字分組與模數專題

日期：2026-11-12
狀態：**外部研究查核 + 題庫系統實作規格草案（尚未開跑新模型，也未聲稱已建立可執行新題庫）**
來源：U = 作者當輪方向；F = 本倉庫原有程式/原始論文；E = 公開外部論文與程式（附來源）；A = 模型提出之可驗證設計。不要將 A 或 E 倒填成作者原稿。

## 0. 作者目標（U）

「得建立題庫系統，像那個模數的就是偏科題，感覺也能試試看。你去看看其他人怎麼重新編碼，是不是像我們這樣壓縮。」

目的不是立刻參加特定比賽，而是先建立**可生長、可擴充題目家族、兼容多種編碼與多種小型網路架構的公平基準**。將 modular multiplication `(a*b) mod p` 視為數學專長題之一，不得以此一科的正確率替代整體數學／程式能力。若有正面結果，再探索與公開模型或正式賽事比較。

## 1. 外部重新編碼方式的研究結果（E）

| 類型 | 實際設計 | 與 SLE 對比／值得測什麼 | 原始來源 |
|---|---|---|---|
| SAIR Digit Transformer | 整數十進位逐字拆成 0–9，另設 BOS/SEP/EQ/EOS/PAD；模型4層、128維、序列上限80。僅傳入原始 a,b,p，模型要自己學運算；超長串截掉後只能答錯，並非壓縮成功 | 這是典型**平面數字 token + 特殊控制符號**，不是階層二進位擴位，也不是結構壓縮 | https://github.com/SAIRcompetition/modular-arithmetic-challenge/blob/main/examples/digit_transformer/model.py |
| SAIR DLP Grokking | 可訓練的 streaming decimal-digit reduction → 共用 residue encoder → **兩個嵌入向量相加**的離散對數啟發瓶頸 → 已訓練 decoder；不允許用 Python 直接求最終模乘答案 | 與我們「先設有利於學習的結構、再讓小網路學習」相近，但這是**數學專用 latent representation / inductive bias**，不是 SLE 詞法編碼，不能將它當成單純 parser 或免費外部計算器 | https://github.com/SAIRcompetition/modular-arithmetic-challenge/blob/main/examples/dlp_grokking/model.py |
| 1位/2位/3位 tokenization | 按十進位 1、2、3 位分組，相當於 base10/base100/base1000，後者 token 較少但詞表更大。EMNLP 2024 實驗中從零訓練時 base10 逐位表示更省資料；微調差異較小 | **字串更短 ≠ 更容易學／更省總成本**；對照 SLE 位元串＋階層標籤很重要 | https://aclanthology.org/2024.findings-emnlp.218/ |
| Position Coupling | 不依普通絕對字元順序，而把**相同位值**的數字位置配對；NeurIPS 2024 論文從1–30位加法泛化到200位 | 和 SLE「高位增加、低位資訊/ID不變」方向相近；但對方是位置表示/歸納偏好，不是動態新增神經元或 SLE 協議 | https://chulheeyun.github.io/publication/cho2024position/ |
| 反向輸出/逐位進位 scratchpad | 讓模型從低位開始輸出、或寫出中間進位與局部計算。ICLR 2024 的小模型研究顯示格式與分步資料能影響學習效率；ICLR 2025 研究專用 scratchpad 和跨位位置耦合，獲得多位加法/乘法長度泛化 | **增加輸出長度反而可能降低學習難度**，須用實際總成本檢驗 | https://proceedings.iclr.cc/paper_files/paper/2024/hash/6bf82fdcbd92b6a7793b3894422d2437-Abstract-Conference.html ; https://arxiv.org/abs/2410.15787 |
| Fourier/群結構、NALU | 模加法的神經網路可學到類週期/Fourier表示；NALU 架構內建適合數值運算的可學習歸納偏好，提高外插能力 | 另一種**將規律壓入權重/架構**而非縮短原始位元碼的方向，應作不同層級的研究比較，不可說它們等同 SLE | https://pair.withgoogle.com/explorables/grokking/ ; https://papers.nips.cc/paper_files/paper/2018/hash/0e64a7b00c83e3d22ce6b3acf2c582b6-Abstract.html |

**核心區別**：SLE 一層資料詞的 `n` 資訊 bit 加 `0` 尾碼，在 raw bit 層並不自動短於普通 n-bit 二進位；另有開場詞、算符詞、句號/層級字元等控制開銷。它的候選優勢是**可規則擴位、詞/協議增量、共享詞典及知識可重用，促進小模型學習、保持/擴充能力**。這是待驗假說，不能用「詞長短」直接證明神經網路壓縮率高。

### SAIR 基準的比較邊界
- 官方 repo `examples/README.md` 列已訓練權重與公開例子。`digit_transformer` 約544k參數，`dlp_grokking` 約6M參數；**前者是逐位 Transformer，後者含模數專用結構**，所以比賽排名並非相同架構下兩種 tokenizer 的純比較。
- 官方案例 README 的公共1100題總準確率為 9.4%（digit）/8.5%（DLP），其 `rules/evaluation.md` 搜尋可見另有12.1%/12.7%不同快照，需以**同一 git commit、同一資料 seed、同一模型權重重新測量**才能報數，不得混用相衝突的文件分數。
- SAIR 正式提交不准外部程式替模型計算 `a*b mod p`。測我們自己的網路亦遵此原則：**教師 oracle 只能製作資料與批改，學生推理路徑不能接入答案 oracle**。

## 2. 題庫系統基本結構：中立題意優先，編碼可插拔（A）

本倉庫已有：
- `experiments/spiral_parser/spiral_dialogue_v03.py` 的 `sle_bank_v03`：腳本式教師/學生用的 stateful curriculum；**並非**這次神經網路公平跑分題庫，也不是從零神經學習的實測。
- `experiments/spiral_parser/spiral_tree_nodes_v06.py` 的 `state.tree.math.operator_branch.highwater`：算符**最高已分配編號**持久存於樹節點，而非由現有節點數推算。**新題庫應重用這類概念，不要覆寫原有歷史程式/重造不相容持久狀態。**
- P028/P030 教學規格：二進位輸入、0/1/STOP 輸出；原題庫 **n1 的 `10` 為合法資料，句號從 n2 的 `110` 正式教導**；升階只進不退，普通數字資料只增高位、舊低位與 ID 不變；新增神經元當下完全保留舊權重，訓練後測自然漂移。

新題庫宜另立 `experiments/spiral_teaching/math_benchmark/`（待實作）：
- `task_schema.py`: 中立 `TaskCase`：`case_id, family, operator, operands(int/bitstring), result, difficulty, digit_width, curriculum_stage, seed, split(train/val/test), flags(edge/carry/etc), provenance, semantic_version`。**這不是模型輸入**，不能把 AST/operator/答案提示洩漏進 student。
- `generators.py`: 以 seed 決定的題目產生器，含合法邊界、均衡樣本、跨位案例與統計分布；初期僅使用 Python 標準庫。
- `oracles.py`: **只供教師/離線驗收**的數學正解函數，附已知極值與隨機 property tests；不可在神經網路推理介面被呼叫。
- `encoding_sle.py`: 原始 SLE 的位/層/版本/詞表，active_END，原資料 ID 擴位；出題前 round-trip 檢查；與原版 script profile 衝突時顯式 profile version，不隱式偷改語義。
- `encoding_binary.py`: 非 SLE 的公平 plain binary / fixed-field / 顯式長度規則；同樣允許學生只有0/1輸入，不用超額的外部特徵。確保固定短長、同教材下編碼的可解性。
- `encoding_alternatives.py`: 可選最低位優先、十進位 digit-as-bits、位值配對／分組等；說明是否增加**位置 embedding 外部先驗**及輸入額外 token。
- `curriculum.py`: 單調升階 state、出題分布、觸發門檻、延後啟用句號、不同任務家族的追加與比例。
- `benchmark.py`: free-run 完整正解、逐算符/未見輸入、跨位、過階後保留率、參數/權重漂移、資料總 bit / token / FLOPs、CPU 時間、顯存與 RAM；保存每seed/每階指標到 JSON/CSV。
- `tests/`: 三種 encoder 的 round-trip、一致正解、純01限制、END 活躍狀態、不同 seed 可重播、split 無交叉及題目去重，特別防止相同**數學題**經不同編碼後同時出現在 train/test。

## 3. 先讓題型可伸縮，不要一次把題目弄長（A）

| 題庫家族 | 最初限制 | 必備困難子集合 | 為何值得學 |
|---|---|---|---|
| B0 基礎 | Echo、NegEcho、Zero、One、CUT、END | 句號未啟用/啟用、output STOP、自主複製 | 與P029/P030銜接 |
| B1 位元邏輯 | AND、OR、XOR、NOT | 全0/全1/不同位、雙參交換 | 最容易驗證位元增長重用 |
| B2 加減 | 2–4資訊位開始 | 0與1、跨位進位/借位、結果溢位、負數政策（是否納入先定義） | 檢查舊位權重是否需協作 |
| B3 乘法 | 2–4位開始 | 零、一、雙位互乘、跨位多個部分積、完整輸出位長 | 與普通加法不同的泛化障礙 |
| B4 除法/取模 | 短整數、除數非零 | 整除、餘數0、商0、較大被除數、除數1 | 比模乘題更普遍的數學能力 |
| B5 模乘專題 | 初始小質數 `p`, 逐步到未見質數與多位數 | `p=2/3/5/7`、不等於訓練質數、`a,b>p`、零餘數 vs 非零、長位數 | SAIR 相似但不可拿偏科成績冒充全能 |
| B6 程式/組合 | 先2步有限運算、後逐步延伸 | 未見算符組合、分支與短循環（需定義安全停止） | 將來評測可執行智慧，不急著本輪訓練 |

每個家族再依 `operand width`、`output width`、`operation count`、`carry count`、`new-prime`、`seen vs unseen composition` 分層。**資料位數和算符詞階不是同一個變數**；只有題庫 manifest 記錄 profile，不偷偷把 n 或題型 ID 送給模型。

### 初期建議
先 B0/B1，然後 B2（2–4位）和 B5（小質數）；B3/B4 待 B2 成功後擴展。題庫可事先生成所有家族的規範與試題，但不要一次塞進單一小模型訓練。數字變長前先測該家族能力，避免長題掩蓋新算符學不會。

## 4. 公平對照與「壓縮」定義（A）

必須分開量測：
1. **串流傳輸壓縮**：平均 raw bit / 題、控制碼開銷、可解析性、token 數、長度分布；
2. **學習資料效率**：達到指定未見測試準確率所需的 unique 題、總題次、教師標籤 bit、optimizer updates / FLOPs；
3. **模型表示效率**：通過的題型/算符/未見組合數 ÷ 主網路參數，以及新加1位對應新增參數與舊權重變化；
4. **全系統總成本**：學生、如需神經轉碼器、兩邊等價純翻譯器、詞表、題庫、訓練與推論成本；
5. **多任務遷移**：學 AND/OR/XOR 後再學 ADD/MUL/MOD 是否更省題、更少忘記舊功能。

用相同中立 TaskCase 對比 SLE / plain binary / 位置耦合 / 反向位序 / 位元分組。**純表示法比較保持網路架構、總參數量、課程、訓練總運算、出題分布固定**；若額外加入 position coupling、scratchpad 或 DLP-specific learned reducer，作獨立的**表示＋歸納偏好**對照，不能說只是換 encoder。

**最重要的反例**：「SLE 的位元流短於普通 2進位」不成立為通則：每詞有結構尾碼、算符及句號。在公平研究中若 SLE 反而多使用 bit，卻使同樣小的學生更快學會更多規則，這是更有力的學習壓縮結果。
