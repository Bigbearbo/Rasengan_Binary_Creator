## 1. 外部重新編碼方式的研究結果（E）

**核心區別**：SLE 一層資料詞的 `n` 資訊 bit 加 `0` 尾碼，在 raw bit 層並不自動短於普通 n-bit 二進位；另有開場詞、算符詞、句號/層級字元等控制開銷。它的候選優勢是**可規則擴位、詞/協議增量、共享詞典及知識可重用，促進小模型學習、保持/擴充能力**。這是待驗假說，不能用「詞長短」直接證明神經網路壓縮率高。

### SAIR 基準的比較邊界
- 官方 repo `examples/README.md` 列已訓練權重與公開例子。`digit_transformer` 約544k參數，`dlp_grokking` 約6M參數；**前者是逐位 Transformer，後者含模數專用結構**，所以比賽排名並非相同架構下兩種 tokenizer 的純比較。
- 官方案例 README 的公共1100題總準確率為 9.4%（digit）/8.5%（DLP），其 `rules/evaluation.md` 搜尋可見另有12.1%/12.7%不同快照，需以**同一 git commit、同一資料 seed、同一模型權重重新測量**才能報數，不得混用相衝突的文件分數。
- SAIR 正式提交不准外部程式替模型計算 `a*b mod p`。測我們自己的網路亦遵此原則：**教師 oracle 只能製作資料與批改，學生推理路徑不能接入答案 oracle**。

## 2. 題庫系統基本結構：中立題意優先，編碼可插拔（A）

本倉庫已有：
- `experiments/spiral_parser/spiral_dialogue_v03.py` 的 `sle_bank_v03`：腳本式教師/學生用的 stateful curriculum；**並非**這次神經網路公平跑分題庫，也不是從零神經學習的實測。
- `experiments/spiral_parser/spiral_tree_nodes_v06.py` 的 `state.tree.math.operator_branch.highwater`：算符**最高已分配編號**持久存於樹節點，而非由現有節點數推算。**新題庫應重用這類概念，不要覆寫原有歷史程式/重造不相容持久狀態。**
- P028/P030 教學規格：二進位輸入、0/1/STOP 輸出；原題庫 **n1 的 `10` 為合法資料，句號從 n2 的 `110` 正式教導**；升階只進不退，普通數字資料只增高位、舊低位與 ID 不變；新增神經元當下完全保留舊權重，訓練後測自然漂移。

新題庫宜另立 `experiments/spiral_teaching/math_benchmark/`（待實作）：
- `task_schema.py`: 中立 `TaskCase`：`case_id, family, operator, operands(int/bitstring), result, difficulty, digit_width, curriculum_stage, seed, split(train/val/test), flags(edge/carry/etc), provenance, semantic_version`。**這不是模型輸入**，不能把 AST/operator/答案提示洩漏進 student。
- `generators.py`: 以 seed 決定的題目產生器，含合法邊界、均衡樣本、跨位案例與統計分布；初期僅使用 Python 標準庫。
- `oracles.py`: **只供教師/離線驗收**的數學正解函數，附已知極值與隨機 property tests；不可在神經網路推理介面被呼叫。
- `encoding_sle.py`: 原始 SLE 的位/層/版本/詞表，active_END，原資料 ID 擴位；出題前 round-trip 檢查；與原版 script profile 衝突時顯式 profile version，不隱式偷改語義。
- `encoding_binary.py`: 非 SLE 的公平 plain binary / fixed-field / 顯式長度規則；同樣允許學生只有0/1輸入，不用超額的外部特徵。確保固定短長、同教材下編碼的可解性。
- `encoding_alternatives.py`: 可選最低位優先、十進位 digit-as-bits、位值配對／分組等；說明是否增加**位置 embedding 外部先驗**及輸入額外 token。
- `curriculum.py`: 單調升階 state、出題分布、觸發門檻、延後啟用句號、不同任務家族的追加與比例。
- `benchmark.py`: free-run 完整正解、逐算符/未見輸入、跨位、過階後保留率、參數/權重漂移、資料總 bit / token / FLOPs、CPU 時間、顯存與 RAM；保存每seed/每階指標到 JSON/CSV。
- `tests/`: 三種 encoder 的 round-trip、一致正解、純01限制、END 活躍狀態、不同 seed 可重播、split 無交叉及題目去重，特別防止相同**數學題**經不同編碼後同時出現在 train/test。

### 題庫架構怎麼兼容（A）

- 在 `TaskCase` 新增`school_level`, `math_domain`, `reasoning_depth`, `output_kind`, `statement_modality`, `bridge_mode`, `source_license`, `provenance`, `source_version`。核心定義仍然是**中立題目語義**，可供 SLE、壓過的 plain binary、其他編碼器對同一道題生成不同位元流。
- 設計`math_curriculum`：基本四則/位運算 → 國中方程/應用 → 高中代數/函數 → 幾何/計數/概率 → 國高中競賽 → 進階數論/模數。**不要硬性排成不可調整的單一路線**；按照學生掌握的技能節點自適應選題，但同一輪公平對照下不同編碼用相同的 AST 題目分布及 budget。
- 文字題轉換為 AST 時必須列出使用的是**人工/外部模型教師標註**，而不是聲稱小模型從位元自行理解原題。幾何題若依賴圖形，明確標記有無給圖、是否用結構化幾何條件替代，禁止偷偷給一邊更多資訊。
- 建立不同領域的**封存未見測試題**，明訂數學等價判準（例如方程組解順序、分數約分、等價代數式）、非法/不唯一解答、輸出規範、無法解的樣本。對照比較在同等參數及訓練資源下能通過幾個**真技能類別**，而非只看 Easy題數。
- 建議每級先自動生成短題以測「新增神經元+1是否保留舊權重、後續自然漂移」；再用封存公開題/原創競賽風格題考察泛化。原始名校競賽題的難度很可能遠超目前小模型，應誠實分項報0分，不以比較失敗否認初期增量學習結果。

**[更新]** B7–B10 國高中數學與正式競賽風格測試是 P031 題庫必要主線，不能只把專門模數題當數學競賽。**[取代]** 僅 B0–B6 算符+模乘的狹義數學題庫。**[原因]** 作者提出應評估學校數學及競賽中多類推理能力，而非只會算數或模數。**[狀態]** 來源和課程綱要已核對；新增題庫尚未實作或實測。

## 3A. 必須把普通二進位也壓到合理水準（U 校正，2026-11-12）

作者指出：「但你還得幫普通二進位壓編碼吧？都不壓是很難比的。」這是**公平性硬條件**：對照組不得是隨便串長 bit 欄位、重複寫完整 opcode 名稱或刻意多放無用符號的弱版本。比較目標是 SLE 與**具備相近語義功能、認真設計過的緊湊普通二進位編碼**，而不是「SLE vs 笨格式」。

### A. 緊湊平面二進位（主要公平對照組）

- 原生數值：已知當前資料資訊寬度 `n_data` 時，直接用 `n_data` bit 表示整數，不加 SLE `0^k` 詞尾。例如 `1` 的 n=2 表示是 `01`，n=3 是 `001`。和 SLE 一樣**高位擴張、低位及數值 ID 不變**，不可把「能增長一 bit」說成 SLE 所獨有。
- 算符：若有 `m` 個當前已啟用算符和一個 END 控制碼，在同一**控制詞分支**用 `b=ceil(log2(m+1))` bit 編碼，舊 ID 不動，END 可用高端保留 ID；詞表擴容時增加控制詞寬。控制碼在語法位置解析，不與資料欄位混淆。
- **教學時序相同**：n=1 時 SLE 尚未啟用句號，平面對照也不必硬加句號；SLE 從 n_op=2 啟用 `110`，對照組同一教學事件才啟用自己的 END。題目是否有 END 的時機和課程需完全對齊。
- **自描述條件相同**：兩方都可依當前合法 `profile` 知道資料寬、算符寬、作用參數數、層級/版本；若讓 SLE 從先前對話獲得 profile，普通對照也有同等資訊，反之亦然。絕不能一組靠宿主知道欄位長度、另一組必須自己判斷所有邊界。
- 在已知結構的低階教材中，`OP + DATA + END` 的位置可由 parser 依 profile 判定。若出現多算符、多層、變長分支，**平面二進位亦需設計合法且無歧義的定界規則**，不能為省 bit 偷省必要資訊。

**可核對示例（示意性 flat profile，不冒充 SLE 原碼）**：
- 共用兩邊有一個2-bit模式/起始詞 `01`；當前有 Echo/NegEcho/Zero 三個算符，flat 控制碼 `00/01/10`，END=`11`；資料寬 n=2，數值1為 `01`。
- SLE：`01|100|010|110`，即 `01100010110`，**11 bits**；flat：`01|10|01|11`，即 `01100111`，**8 bits**；兩者表示同一個「Zero(1)，句號」任務。
- `|` 只是展示用，不是神經網路收到的新 token。兩者模型 input 只能收到純 `0/1`，output 也遵循相同的 `0/1/STOP` 限制。
- 若測試「宿主已有封包結束訊號，不需句號」變體，**兩邊都同時取消原生 END 成本**並另列結果，不能只為 flat 免掉 END。

### B. 公平而更強的壓縮變體（不可只挑一個弱對照）

1. **Flat-Fixed**：每階最短固定欄位（數字 n_data 位、算符 b 位、語法所必需的欄位而已）。這是主要學習基準，穩定、容易解析/增量擴位。
2. **Flat-SelfDelimited**：沒有可事先共享的長度時，使用事先定義的長度前綴（如 Elias gamma 或固定小長度欄位）+ bit packed 值；若允許共享 stage/profile，也讓 SLE 享有同一級別的共享資訊。量測其額外解析/教學成本。
3. **Flat-Frequency**：當 opcodes、資料值或題型分布高度偏斜，可使用 Huffman/算術編碼等頻率式壓縮以減少平均傳輸 bits；但要把碼表/分布更新、壓縮/解壓 CPU、流式解碼與版本開銷計入。若輸入被壓成高熵、不利神經網路直接學習，這是可能的真實代價，不可用**外部解碼後再交給 flat 學生**、卻要求 SLE 學生直接讀 raw 碼，來製造不公平。
4. **Flat-Hierarchical（結構控制組）**：允許階層、局部詞典、版本與保留控制詞，但不使用 SLE 尾碼格式，測 SLE 優勢是來自**階層可擴展原則**還是特定尾碼。
5. **SLE-Original**：保留原始詞尾、句號啟用時機、層級和擴位規則，不為了追求 bit 數而偷偷改掉 SLE 語法。若要另提 `SLE-Compact` 變體，必須另標協議版本、不能用它冒充原作者原稿。

### C. 必須明列的理論和評測注意

- 對**均勻遍歷所有 `2^n` 種 n-bit 數值**，單純的無損編碼不可能把所有值都縮到少於 n bit。公平 baseline 主要能省的是不必要的**結構尾碼、運算符和重複欄位**；若教材數值分布高度不均，頻率壓縮才可能降低平均數值 bit 成本。
- **壓縮率與學習效率不是同一件事**。強壓縮會降低傳輸量，也可能讓可學規律難以辨認，或提高 decoder/codebook 開銷。要同時報 raw bits/題、解碼 CPU/記憶體、達標題次、訓練 FLOPs、未見題正確率、動態升階成本及總模型＋decoder 成本。
- 基線**不可以故意缺少** SLE 已有的版本擴容、特殊控制詞延後啟用與數字高位擴張能力，也不可要求它使用不必要的 ASCII、十進位或冗長標籤。
- 基線**也不能太強到引入免費答案**：編碼/解析器只做合法表示轉換，不對運算任務計算答案、不幫學生解數學。先使用相同中立 AST/標籤生成數學題，再編成雙方合法 raw bitstream；所有學生共享相同語義課程/評估 split。
- 不必強制所有輸出字串等長；輸出同一數學語義的正確性使用事先固定的等價標準與純翻譯器驗收。若測比賽共通格式，另外實測神經輸出轉碼器及其成本。

### D. 建議實作與驗收

Codex 在開新神經網路訓練之前，先完成 `Flat-Fixed`、`Flat-SelfDelimited`、`SLE-Original` 的編/解碼器及同一 TaskCase 一致性測試，逐階列出各自 `header/op/data/END/total` bit breakdown。之後再加 `Flat-Frequency` 和 `Flat-Hierarchical`（若需要）。測試要涵蓋：n=1 無句號、n=2 句號啟用、n=2→3 高位擴張、3個以上算符、雙資料參數、profile 與詞典高水位、無效控制碼拒絕、跨版合法解碼及 no-answer-leakage。

**[更新]** ordinary binary baseline must be legitimately compact and growable. **[取代]** 只拿未壓縮的 plain binary 作單一對照。**[原因]** 不公平的弱對照不能驗證 SLE 優勢。**[狀態]** 詞碼設計與例題可手算核對；尚未提交編碼器或性能實測。

## 4. 公平對照與「壓縮」定義（A）

必須分開量測：
1. **串流傳輸壓縮**：平均 raw bit / 題、控制碼開銷、可解析性、token 數、長度分布；
2. **學習資料效率**：達到指定未見測試準確率所需的 unique 題、總題次、教師標籤 bit、optimizer updates / FLOPs；
3. **模型表示效率**：通過的題型/算符/未見組合數 ÷ 主網路參數，以及新加1位對應新增參數與舊權重變化；
4. **全系統總成本**：學生、如需神經轉碼器、兩邊等價純翻譯器、詞表、題庫、訓練與推論成本；
5. **多任務遷移**：學 AND/OR/XOR 後再學 ADD/MUL/MOD 是否更省題、更少忘記舊功能。

用相同中立 TaskCase 對比 SLE / plain binary / 位置耦合 / 反向位序 / 位元分組。**純表示法比較保持網路架構、總參數量、課程、訓練總運算、出題分布固定**；若額外加入 position coupling、scratchpad 或 DLP-specific learned reducer，作獨立的**表示＋歸納偏好**對照，不能說只是換 encoder。

**最重要的反例**：「SLE 的位元流短於普通 2進位」不成立為通則：每詞有結構尾碼、算符及句號。在公平研究中若 SLE 反而多使用 bit，卻使同樣小的學生更快學會更多規則，這是更有力的學習壓縮結果。
