# P027｜螺旋語 Echo：逐詞監督與教材完整覆蓋（Codex 執行指令）

日期：2026-11-12  
性質：研究指揮規格；這份文件不是已完成實驗的報告。  
來源角色：U＝使用者研究方向；A＝本輪 ChatGPT 實驗設計；P026 數據＝Codex 提供、尚待按程式核對的執行報告。  
本輪優先：**先驗證教學與題目調度，再考慮擴大網路。**

## 一、研究問題與已有證據

使用者的設計是螺旋語 Echo 題，模型每一步只輸出 `0`、`1` 或 `STOP`，將已輸出內容接回完整題目後再推理下一詞；初期固定的算符前綴可被小模型視為不重要的資訊。**不必先全串答對才有學習機會，每一個輸出位置都能提供監督訊號。**

P026 報告稱：
- Direct MLP：69 輸入（23 位置 × 3 one-hot）、16 tanh 隱藏神經元、3 softmax，1,171 參數。
- 13-bit raw 題目，9-bit 答案＋STOP；192 教材／64 保留題。種子 101、202、303。
- 每 seed 20,000 題次，逐詞 +1/−1 即時獎懲，錯答整題重試，**整串全對才換下一題**；不把正解 token 作為交叉熵標籤。
- 實際見題數：8／1／12；保留集完整答案皆 0/64。兩 seed 有固定長度停止的改善，不能當成複製學會。
- 歷史實作：`outputs/sle-research-review/echo_bit_feedback.py`；`work/sle-research-review/echo-bit-feedback-20261112/compact.json`。這些是 Codex 工作目錄的報告路徑，**先確認本機實際存在，不能假設已同步到 Git**。

**判斷：**報告中的教材卡關是明確的實驗設計問題；但「這是模型失敗的唯一原因」尚未證實。P026 的 `(1/3)^10` 只能描述均勻猜整串的示意機率，不能用來否定逐詞監督學習；不要把「訓練時逐詞正解」與「驗收時整串全對」混為一談。

## 二、先唯讀核對，避免誤修

1. 找到 P026 原始程式、dataset split、計分與訓練 trace；核對檔案、commit、參數量、輸入 one-hot 順序、STOP 邊界、訓練更新、抽樣策略、洗牌規則、是否有輸出標籤洩漏。
2. 確認 `20,000 題次僅看 1 題` 是否確實來自「整串正確才能前進」；提供程式證據（檔案與行號），而不是只根據報告猜測。
3. 核對 9-bit 答案的定義，尤其最後的 0 是否屬於螺旋語資料詞；勿擅自刪除尾碼、改動 `0100` 等版本語法、改題型或變更 192/64 原始資料。
4. 保留 P026 原檔、原 seed、原輸出與歷史報告，**不得覆寫**。在新檔或新實驗目錄執行。

## 三、第一階段 P027A：只更換教材調度（獎懲法對照）

目的：檢驗題目覆蓋與卡關對 P026 的影響；只改一個主要因素。

- 保持 P026 的網路架構、輸入格式、+1/−1 回饋、探索/梯度/optimizer/learning rate/baseline、最大輸出步數、資料切分和 seeds 原樣。
- 唯一主要改動：**每次題目作答結束即換下一題，答錯也換。** 將全部 192 題每輪以 seed 控制洗牌、各出一次，再重洗下一輪；嚴禁「整串全對才進入下一題」。
- 每 seed 20,000 題次，記錄 192 題各被看到幾次、題次、token 更新次數、時間、訓練與保留集結果。理論上若完整執行，每題應至少看 104 次（20,000＝104×192＋32），實際若因時間上限中斷則據實回報。
- 注意：此階段對照 P026 **只能隔離題目調度**；若其他隨機狀態因此改變，需在報告說明。不得說因此就證明逐詞監督有效。

## 四、第二階段 P027B：明確正解的逐詞監督（主要方案）

目的：檢驗小網路在**教師已知每個正確輸出 token** 時是否能學到複製規則。採用 P027A 的「完整洗牌輪替、答錯也換題」教材調度。

- 保持 1,171 參數 MLP（69→16 tanh→3 softmax）、同一資料切分與同一 3 個 seeds、同一上下文長度與分隔符、同一輸出詞表，**本輪不要加大網路，也不要引入 Transformer、RNN 或新詞表**。
- 教材為 `題目｜正解前綴`，目標 token 為緊接的正解 `0`、`1`、`STOP`；用 **cross-entropy** 直接訓練正確 token。教師在訓練時可使用正確前綴（teacher forcing），不需要先靠機率碰巧選到正確 token；不要再只回傳 +1/−1 標量。
- 每題的 9 個 bit 與 1 個 STOP **都應有監督樣本**；給定 `a_1…a_9`，訓練資料為：
  `題目｜` → `a_1`；
  `題目｜a_1` → `a_2`；
  …；
  `題目｜a_1…a_9` → `STOP`。
- 可每 token 一次 Adam 更新，或把同一題的 token loss 聚合再更新；但**必須明確記錄使用哪種更新策略、更新次數、實際訓練 token 數**，且不要把「一次題目」偷換為「一次參數更新」。
- 為可比較性，至少回報兩個相同預算切點：**20,000 題目曝光**與**約 160,000 token 更新／學習樣本曝光**（如更新策略不同，說明如何等效）。保存每 seed 曲線，不可只挑成功的一個 seed。
- 若用正確前綴訓練，請在評估時嚴格使用**模型自己的輸出前綴**，不能把 teacher forcing 下的 token accuracy 冒充自由生成能力。允許額外報告 teacher-forced 指標，但務必分欄。
- 若某些題目的答案 bit 並非單純 9 長度，應先核實原 dataset 定義；先不自行改規格。外部題庫答案生成器可作評分 oracle，不能把答案直接混入模型測試輸入。

### 追加診斷（先不納入主實驗變因）

如果 P027B 的 teacher-forced token accuracy 很高、free-run 全串正確率仍低，分析 exposure bias，必要時另開 P027C：讓模型在自己產生的**錯誤前綴**上仍收到該位置正確 token 的監督標籤；和 P027B 使用相同出題規則與容量，單獨比較。**不要在 P027B 未完成前混入此改動。**

## 五、評估與驗收（比單一整串分數更重要）

請在訓練集 192 題與保留集 64 題分別量測，且明確標註先前保留集已用於研究分析，**不是全新盲測集**：

1. teacher-forced 下一 token 正確率、cross-entropy，分別統計 bit 與 STOP。
2. free-run greedy 完整答對題數（**9 個 bit 全對，且正確時機 STOP**）；不能只抽樣偶然成功算掌握。
3. free-run 各位置 bit 正確率（1–9）、平均 bit 正確率、第一錯誤位置分布、前綴正確長度。
4. STOP 位置分布、提早停止、漏停止、超上限；固定正確長度只代表學會計數，不代表學會 Echo。
5. 教材覆蓋度：每題曝光次數的最小/最大/平均、unique_seen，證明完成至少一輪（若有）。
6. 三 seeds 各自學習曲線（題數/token 更新數/耗時、訓練/保留成績）；不得只報最佳 seed。
7. 不能只用 train performance 宣稱泛化；如果已見過所有 256 個可區分題目，應坦承同長度無法再造未見內容的新盲集，下一階段再另做長度泛化。

### 必過的程式測試

- 從同一題生成的全部 `題目｜正確答案前綴` 與目標逐一匹配，末位必須 STOP；不可把未來答案寫進輸入。
- `題目｜`、`題目｜首位`、`題目｜全部9位` 等邊界位置長度與 one-hot 檢查；與原 23×3 輸入格式一致。
- 192 題每輪恰出一次，答錯也會前進；20,000 題次每題最少出現 104 次（若按完整洗牌輪次執行）。
- training 和 evaluation 嚴格分離；評估 free-run 不用正解前綴，不偷看答案標籤、不更新權重。
- 交叉熵梯度 finite-difference 或可對照框架核查；固定 seed 重跑主要指標與權重應可重現。
- 早停、漏停、錯 bit、STOP 正確但內容錯、輸入達最大位置等測試通過。

## 七、決策標準

此次研究不是追求一次跑出最好分數，而是要分辨：
- P027A 比 P026 改善：可能是教材覆蓋問題。
- P027B 比 P027A 改善：可能來自明確 token 標籤、teacher forcing 或優化程序（**不是嚴格單變因結論**）。
- P027B 的訓練 token 準確率高、free-run 差：優先查自回歸錯誤累積與前綴分布差異。
- P027B 的 token 準確率仍差：優先查輸入、標籤、梯度、架構表示能力，再考慮擴大模型。

**不可用全串成功率作為唯一教學訊號；全串成功率仍可作為最終驗收標準。**
