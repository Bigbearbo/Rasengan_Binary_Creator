## 3. 先確認模型實際得到的問題

### 3.1 教師懂題目，不代表學生看得到必要資訊

以下為 A 類檢查法：從真正傳給 `forward` 的 raw01／張量反查一次題意、輸出目標、padding、遮罩、前綴與游標。教師可以用 parser 或 oracle 產生標籤；如果學生的推論介面本來限定 raw01，就不能在評估時額外把詞界、答案長度、解析樹或算好的答案餵進去。

若這些輔助資訊本來就是要比較的設計，將它們明列為額外條件，而非隱藏在資料前處理內。題末 END 與生成動作 STOP 也需分開：會停在固定長度，可能只學會格式；內容答對與停止位置正確要分別記錄。

### 3.2 覆蓋表要記角色

建議至少按「算符 × 輸入／輸出角色 × 詞位 × 資訊 bit」統計實際曝光的 0／1、獨立完整題數、重複次數與必要組合。不能把一個數值在答案出現，直接等同它曾在第一輸入詞出現。也不能把題庫有 900 題，當作學生已實際看過 900 題。

一個簡單的 A 類邏輯例子：若某個輸出角色的第 j 位在所有相關教材都為 0，則「正確複製」與「其他位複製、第 j 位固定 0」都可能符合那部分教材。其他角色、參數共享或先驗仍可能幫模型區分，所以不能據此說整個模型絕不可能泛化；但它提醒我們，失敗同時可能涉及教材支援不足，不能直接歸因編碼或容量。

資料少不自動要求加入更多資料。若研究的正是從稀疏例子學規律，缺少組合是實驗條件；需要清楚命名並設對照。若只是意外漏教，則先修教材或調度再談架構上限。

### 3.3 監督方式與訓練量不可暗中改變

逐 bit 交叉熵、整題 scalar 獎勵、模型自生前綴、教師正確前綴，是不同教學條件。一次改多項可以比較整個方案，但不能事後把收益全部歸給其中一項。[P027][E01] 正是這種歸因邊界的現成案例。

等題數也不等於等學習權重。在 AE1 每詞 6 bit 的設定，E1 的正確答案連 STOP 是 7 個 target，E4 是 25 個。若每個 target 更新一次，同樣 900 題會分別產生 6,300 與 22,500 次更新。改成每題平均 loss 後更新一次，會改變任務加權及 optimizer 時序；這是新設計，不是無影響的加速。

## 4. 訓練程式的最小診斷

本節是將 S04、S05 轉為本案的 A 類工作法。只在新寫程式、修改相關數學、或已有具體異常時使用；已有可信驗證且沒有相關改動，不必為每次續訓重做整套。

| 診斷 | 要回答什麼 | 結果不能代表什麼 |
| --- | --- | --- |
| 極少量固定題的擬合 | 在容量足夠、沒有矛盾標籤的前提下，系統能否把簡單教材學好 | 不代表正式課程須滿分、不代表泛化，也不保證程式完全正確 |
| 中央差分與手寫 gradient 對照 | forward、loss、backward 的局部數學是否相符 | 不代表教材分割或研究對照合理 |
| 真正張量與標籤核對 | 位移、前綴、mask、STOP、padding 是否一致，是否洩漏當前答案 | loss 下降不能代替這項檢查 |
| 儲存／載入小步續訓對照 | 同一完整狀態接續時能否重現指定範圍 | 只核對最終權重不代表中途軌跡已被重播 |
| 無關輸入擾動／對照前綴 | 輸出是否受到理論上無關資訊影響 | 單一反例不直接證明內部機制或普遍失敗 |

小批除錯可暫時關閉正則化，使用另立的診斷資料和狀態；目標是合理低的 loss 與正確輸出，不要求浮點交叉熵恰等於零。不要拿正式未教測試題做這種擬合。

手寫 tanh／softmax 的數值檢查可用 float64、中央差分、固定隨機性，抽查每個參數群和 bias；誤差門檻需依尺度與精度設定。正式訓練若用 float32，雙精度是診斷參考，不應無聲替換其數值語義。[S05]

## 5. 如何調訓練，避免盲目堆方法

### 5.1 先判斷缺口，再選超參數

訓練與驗證都差，可能是實作、資料支援、優化、容量或預算問題；訓練很好而新組合差，才比較值得查捷徑與泛化。這是排查順序，不能由一條曲線直接確診。

S06 提出的初始化是 `W ~ U[-sqrt(6/(fan_in+fan_out)), +sqrt(6/(fan_in+fan_out))]`。它提供觀察激活／梯度尺度的理由，但不是所有 tanh 網路的通用修復。新建模型可採此類標準起點；續訓比較應保留已有初始化與權重，除非研究問題就是重新初始化。[S06]

學習率也應視為候選。S07 的 0.001 與 S04 作者實務使用的 0.0003，已足以提醒我們沒有唯一神奇數字。若要比較兩者，從同一完整狀態分支，保持教材、更新定義及預算一致；若同時改課序、複習比例，就只能比較整套政策。

Dropout、weight decay、梯度裁剪、換激活或換 optimizer 都會改變訓練。先提出可被反駁的原因，再決定是否值得加一個對照；不要一次全加，也不要在看過測試後反覆追參數，最後只報成功者。損失仍下降但整題率停住時，可先檢查錯題和正確答案的機率差距，而非立刻加大模型。

### 5.2 完整續訓狀態

Adam 的 m、v、t 參與更新，因此只載權重的重啟與原狀態續訓是不同處理。[S07] 本案建議保存模型參數、optimizer 狀態、學習率／schedule、增長參數的出生步策略、資料課序與增長 RNG、已用預算，以及版本／dtype／執行設定。這份保存清單是工程推導；並不宣稱保留每個狀態永遠優於重置。

要問的是「同一個學生繼續學」還是「換一種重新開始的策略」。兩者都能研究，但不能由 checkpoint 載入程式悄悄替實驗作選擇。模型變寬後的新參數如何初始化 m／v，以及偏差修正使用全域 t 或出生後步數，也需先寫清楚，不能把自訂規則叫作標準 Adam 已驗證的最佳做法。

### 5.3 正確前綴與自行生成

Teacher forcing 是訓練時提供正確的前面答案；自由生成則把模型自己產生的答案繼續送入。S08 說明兩者可能出現分布差異。本案評分應以預定推論方式的完整生成為主，teacher-forced 準確率／loss 作定位工具。

先讀模型程式再套機制：若模型只讀生成長度或游標、不讀前綴內容，不能說它因前一 bit 答錯而被錯誤前綴帶偏。若生成在首次錯誤前就錯了，該處也不能全怪先前自生錯誤。Scheduled sampling 在本報告只是參考文獻，不是直接要求採用的新訓練方式。

一個 A 類邏輯不變量：在權重、初始狀態、輸入介面、mask 與確定性 greedy 規則都相同的前提下，若給正確前綴時每一步含 STOP 的 argmax 都正確，自由生成也應整串正確。若仍不一致，先查索引、停止、狀態或評估介面差異，不能直接解釋為錯誤累積。這裡要求的是同一題每一步全對，不是教師前綴平均率很高。

## 6. 課程、升階與保留

### 6.1 四件事分開定義

| 名稱 | 決定什麼 | 合理的證據形式 |
| --- | --- | --- |
| 升課政策 | 何時開始新難度、如何分配練習 | 熟練度、進步速度、保留情況或固定課程 |
| 本輪停止 | 何時結束觀察 | 事前有限預算、已定停止條件、實作失敗 |
| 研究成功判準 | 這個假說本輪是否得到支持 | 事前指標與相應對照；未達照報 |
| 最終可靠性 | 是否足以承擔指定用途 | 與實際用途相符的錯誤容忍、覆蓋與壓力測試 |

S01 直接支持未滿分進階；S02、S03 則支持把課程安排看成學習效率問題。對本案，95% 可作前瞻參考，仍是 A 類工程選擇。原實驗「兩輪全對」未達的歷史判定保留，改進下一輪政策不等於回寫舊 PASS。

### 6.2 門檻一定要附分母

若門檻為 `correct / N >= 0.95`，實際需求為 `ceil(0.95*N)`：

| N | 至少答對 | 最多答錯 |
| ---: | ---: | ---: |
| 4 | 4 | 0 |
| 8 | 8 | 0 |
| 16 | 16 | 0 |
| 20 | 19 | 1 |
| 32 | 31 | 1 |
| 900 | 855 | 45 |

這是算術，不是統計信心保證。小集合若是全部合法題，可報有限真值表的完整結果；若要估計更大分布，幾題不能代表穩定的「95% 能力」。對同一固定集合重測，若權重和生成都確定性相同，不會因重測次數增加就得到新的獨立樣本。

每 bit 95% 與整題 95% 也不能混用。僅作數學示意：假設 20 個 bit 的正確事件彼此獨立且各為 0.95，整串機率是 `0.95^20 ≈ 35.85%`。真實錯誤未必獨立；這不是本模型的估計，只是兩種指標不同的例子。

### 6.3 繼續學，可以同時補弱點

建議先用可解釋的固定課程或簡單混課，記錄各課進展；有實際證據顯示排程是瓶頸，再比較自動教師。S03 顯示均勻基線不弱，S10 則提供簡單複習的經驗；兩者都沒有替本案定出最佳比例。

舊能力保留需追同一批題的正確→錯誤、錯誤→正確及共同正確，並保留每課曲線。可以分報相對起點的退步和相對歷史最佳的遺忘；兩者回答不同問題。中途掉分後恢復，不應被描述成永久失敗。

舊語義以目前格式複習、回放歷史 raw 格式、另外測歷史格式相容，是三種不同設定。P029 的原要求是不回教／回測舊 raw 階；不能用本手冊改寫它。其他新實驗是否混教、混教多少，應由該研究問題決定。

S11 的 delayed generalization 提醒我們，訓練集先好、驗證後好是可能的；它也沒有保證任何失敗只要一直跑就會成功。若要研究長訓練，另立有限預算並保留失敗；不要把「等頓悟」當作未記帳的無限續訓。

## 7. 網路長大時，哪些東西必須分開看

### 7.1 三個觀測點

網路 shape 擴大後，先量同一個舊 raw 輸入的 logits 是否保持；再量相同語義改成新格式後的立即表現；最後量追加訓練的恢復、新技能與成本。第一項是工程遷移，後兩項才直接回答格式升階的學習問題。

升級瞬間保留函數，不代表後續訓練軌跡等價。即使搬了 optimizer 狀態，參數化和梯度路徑也可能改變；「升級時輸出保存」與「之後如何學習」是不同主張。實際浮點 logits 的比較容差要依 dtype、運算次序訂定，數學等價不必然逐 bit 相同。這是 A 類工程推論，不另要求升級後若干步與未升級模型保持一致。

Net2Net 提供保函數成長方法，但輸入換碼並不在「相同輸入、相同函數」保證內。它的加深方法要求 `φ(Iφ(v)) = φ(v)`；ReLU 滿足，一般 tanh 不滿足。所以不能在 tanh MLP 中直接插入 identity 權重，再宣稱函數一定不變。[S09]

### 7.2 一個可由公式檢查的實作風險

對 `y = W2 tanh(W1 x + b1) + b2`，新增隱藏單元若輸入側非退化隨機初始化、輸出權重為 0，就能在相同 x 保留舊 logits。第一次更新時，新輸入側梯度因輸出權重為 0 而為 0；新輸出側通常仍可先學，之後新單元才參與。這是 A 類數學推導，本輪沒有實跑此案例。

如果新輸入權重、新隱藏 bias、新輸出權重及新 optimizer 動量全為 0，在沒有額外噪聲／耦合的普通梯度更新下，tanh 新單元可能一直為 0、兩側都學不起來。不能只因參數數量變大，就假定有效容量已增加。

另有複製舊單元並分攤輸出權重的擴寬方式，但要處理對稱；加噪打破對稱時，需承認從精確保存改為近似保存。[S09] 本案不要求永久凍結舊參數；允許新舊共同調整，只需把保留效果與訓練成本量出來。

## 8. 本專案已累積的實驗經驗

以下是原作者的歷史實測或前輪視窗 GPT 的已執行診斷。本輪重新閱讀並整理，沒有重跑這些模型。各結論只覆蓋原實驗條件。

### 8.1 P027：換題政策足以讓相同小網路大幅改變

同一個 1,171 參數 MLP，保持原獎懲訓練，只把「全對才換題」改為每題都前進，三個 seed 的保留題由全部 0/64 變成 64/64、60/64、64/64。卡題組各只見過 8、1、12 種題；其中一位呈現兩萬題次仍只有一種。事前指定的同 100,000 更新 checkpoint 也呈現相同主要差異。[E01]

可沿用的經驗：記錄真正曝光的獨立題數，先排除教材阻塞。這不表示所有獎勵學習都不好，也不表示任何任務都不需增大網路。另組交叉熵＋正解前綴三 seed 全部 64/64，但它同時改了兩項，不能只歸功於 loss。

### 8.2 P029：末階適應快，累積成本不一致較低

固定 1,171 參數，逐階資料寬度 n1→8；這不是物理擴網。在 n8 的追加呈現題次為 960／768／768，直接從 n8 開始的對照為 2304／2304／2880。[E02]

| Seed | 逐階全程 optimizer 更新 | 直接 n8 更新 | 逐階／直接 n8 test |
| --- | ---: | ---: | --- |
| 101 | 33,850 | 23,040 | 32/32；32/32 |
| 202 | 24,712 | 23,040 | 30/32；31/32 |
| 303 | 24,708 | 28,800 | 31/32；32/32 |

結論是末階再適應更快，並未顯示總成本或 test 全面較好。若實際生命週期要求前面各階都先可用，直接 n8 也沒有提供同樣的服務歷史。P029 的 95% 門檻在 4／8／16 題驗證集仍等同全對；不回測舊階意味舊階保留未知，不能補寫成通過。

### 8.3 P030：局部遷移與新技能干擾可同時存在

Echo 算符擴位後，持續學生的追加題次為 132／156／180；相同當前 shape 從零開始是 288／276／288，但 test 每人只有一題。加入 Neg 後，成長組均達原 3,000 題上限而未過 validation，並出現同 raw Echo 題由對變錯。[E03]

經驗是局部升階收益與後續干擾需要分別量，不能只憑其中一個概括整套成長方案。此處 Neg 是資訊位 0／1 互補、結構尾零保留，不能用它的結果代替另一種序列順序反轉任務。

### 8.4 P035：已經有格式對照，也有其明確邊界

SLE／緊湊階層格式 × 固定／成長網路 × 三 seed，共 12 學生。已教題全部 144/144；未教輸入值面板為 SLE 5/24、緊湊格式 0/24。這是值得保留的有限正面訊號；SLE 特有成長收益的配對 interaction 為 0、−1、0，沒有顯示相應優勢。[E04]

雙方已擁有穩定 ID、high-water mark、低位保留與局部成長權利；共同輸出是 SLE 格式。因此它測的是輸入編碼與容量時序，尚非各自 native 輸入＋輸出的完整比較。固定組每學生 15,000 題、成長組 17,973 題：等 MAC 下的曝光不同，不能把收益全歸權重移植。

另有同 raw 函數保存卻換碼入口失敗的直接記錄：op 擴位前合計 89/96，換碼後 0/96，再訓練後 84/96。加入 Neg 後，Echo 84/96→77/96，實際是失去 8 題，另有原先錯誤的 1 題新答對，不能只稱忘了 7 題。值 4、6 也曾在答案角色出現，不是所有角色完全未見。

### 8.5 PR56：淨分數會掩蓋輸出受干擾的範圍

前輪視窗 GPT 對 PR49 固定終點做過真正的唯讀 E3 介入。seed202 僅改答案無關的第四詞，總分 879/900→876/900；完整輸出卻有 37 題改變，其中原對變錯 20、原錯變對 17。該輪有 205,448 次 forward、0 optimizer；本輪未重跑。[E05]

可沿用的經驗：保留逐題配對，不只看總分差。這是固定權重的行為診斷，不能當作新的訓練成果，亦不直接揭露唯一內部機制。

### 8.6 PR58：修正研究優先順序，保留歷史判準

## 10. 如何把知識用在螺旋語的優勢比較

先寫清欲估計的效果。輸入格式本身、格式＋輸出、課程政策、擴網策略，是不同問題。一輪可以比較整套系統，但若目的是解釋哪個因素有效，就需要相應控制。

P035 已做輸入編碼 × 容量時序，因此下一個有價值的候選，是在較小網路上比較兩種格式各自 native 輸入＋輸出，使用相同中立語義題流與升階事件，保留雙方穩定 ID 和局部擴階能力。先比較格式升階的適應，再另外加入 Neg 等新技能，避免第一次就把換碼、擴網、換 optimizer 和新任務全綁在一起。這是尚未執行的 A 類設計方向，不是已凍結 protocol。

主要看固定預算後各課完整生成、升階後恢復曲線、舊技能保留、以及從最初開始的總成本。達到 90／95／99% 的成本可作曲線摘要；只在預定測點觀察到跨線，報「首次觀察達標」，不能冒稱精確首次時刻。未達者記為預算內未達，不刪掉失敗 seed。

公平不是所有量都能同時相等。兩種 native 輸出長度不同時，等語義題數、等 target 更新、等 MAC、等時間是不同比較。建議指定一個主要預算軸，同時公開其他消耗；至少保留同語義工作量與同計算預算兩種讀法。模型參數數相近，也不等於運算、儲存或工程投入完全相同。

成本分訓練、評估、獨立重播、調參搜尋、失敗重試、codec／詞表更新、儲存及傳輸；未量到就標未量，不把 dense MAC 冒充全系統 FLOPs。將一次部署後的運行成本與研究者搜尋成本分列，避免掩蓋它們，也避免把所有研究成本不加區分地攤給每次使用。
