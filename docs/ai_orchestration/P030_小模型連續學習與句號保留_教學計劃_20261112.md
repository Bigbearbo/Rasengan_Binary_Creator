## 現行架構修正（U，2026-11-12）：共用螺旋語數學題庫 + 前後翻譯網路

作者最新要求：「**題庫共用，都是螺旋語，需要你們把數學題變成螺旋語，之後神經網路可以再接一個翻譯網路，後面接輸出翻譯網路。**」**本段優先於本文件較早的「模型直接產生通用答案」比賽設計**。兩條正式主線（NN 學生與倉鼠 VM 學生）從**同一份 SLE 數學題庫的相同 0/1 raw 題目**學數學；只有學生內部的學習方式不同。

正式主線：
```text
原始數學題（國高中/競賽題，未必是自然語言）
 → 教師離線語義轉換 / 可驗證的數學題生成器
 → versioned SLE 編碼器、語法樹、句號規則
 → 同一份 SLE 題庫與標準 SLE 答案
    ├→ 連續成長 NN（input 0/1；output 0/1/STOP）
    └→ 程式型倉鼠 VM（相同題目 raw bits；輸出依其 VM 協議）
 → 各自解題結果 + 教師離線評分
```

神經網路後續可發展成**三段式可拆卸架構**：
```text
自然語言/符號數學題
   →【輸入翻譯神經網路】→ SLE
   →【核心數學神經網路】→ SLE 答案
   →【輸出翻譯神經網路】→ 通用數學格式/ASCII
```
- **輸入翻譯網路**只負責忠實保留題目語義、翻成 SLE；不可先求解再把答案塞進題目，訓練時需用題意/SLE 配對語料、驗證翻譯 round-trip。初期優先由教師離線產 SLE 題庫；此網路是日後可替換模組，不應阻礙核心學生先學數學。
- **輸出翻譯網路**只負責核心學生產生的 SLE 答案轉成人類可讀/比賽要求的格式，不得看原題、標準答案或代算。可獨立訓練，同時測固定確定性轉碼器作便宜基線。
- 主學生在 SLE 上學數學，**不必自己學 ASCII 或文字數學讀題**；若要直接通用輸出，是額外的分離對照，不是正式主線。
- **所有國高中題必須先定義可保真 SLE 語義**：原本只有 Echo/Neg/Zero/CUT 等有限詞表，新加 `+`、`-`、`=`、未知量、分數、函數、幾何等必須有明確算符 ID、參數類別、作用域、profile/version 和合法對應的語法，否則記 `pending-vocabulary`，**不可以猜一個 01 字串冒充已定義詞**。
- **真正共享的是同一份 raw 0/1 題庫，不只是題目概念**；使用相同 `case_id`、`profile/version`、`raw_question_bits`、`raw_expected_answer_bits`、split、教師評分與 provenance。NN 和 VM 若需要不同載入/收尾介面，應採 adapter，不得各自改寫題意。
- P031 補充有細節。SLE vs 認真壓縮過的普通二進位**只作獨立編碼對照**；不得因此把 VM 主線改成 plain binary。

**[更新]** 共用 SLE 題庫是主線；神經網路可前接輸入翻譯器、後接輸出翻譯器。
**[取代]** 讓 NN/VM 使用不同日常數學編碼；或把核心 NN 自行產生 ASCII 當作必要前提。
**[原因]** 雙學生的研究目標是比較學習數學的機制，編碼優勢和翻譯模組效率另行比較。
**[狀態]** 規格確定，尚未建成這套跨 VM/NN 的共同題庫與神經翻譯器。

## 一、研究目標（不要偷換）

用比 P029 1171 參數 MLP 稍大的神經網路，以**同一個學生、持續沿用權重與 optimizer 狀態**，完成由短題到更複雜語言的學習歷程：Echo（初期無句號）→ NegEcho / Zero → 句號正式啟用 → 新算符和升階 → 雙運算元 → 二層語言 / 版本。考察新階與新任務能否**受惠於先前已學能力**；目前不要求證明整個課程比直接學最難任務的**總成本**更低，但成本必須完整紀錄，不得刪去前段的花費。

不要把研究目標換成單純擴大 8-bit Echo 資料、使用單一固定長度題、重設權重的分段模型或腳本化解析器代答。P029 已提供原長度 Echo 的連續升階可行性報告（各 seed n=8 未教題 32/32、30/32、31/32）；新任務應向**語法與操作複雜度**增加，而不是只增加位元長度。

## 二、嚴格 I/O：只用 01 輸入，01 + STOP 輸出

- **輸入的外部 token 字母表恰好為 `0`、`1`**。不能再額外給模型題答分隔符 `｜`、`WB`、`END`、特製 `PAD` token、算符 ID、解析樹結果、答案長度或題型特徵。內部 position embedding / length mask / padding mask 是計算實作，不是新語言符號；若使用 mask，須記錄如何保證沒有把 oracle 的邊界/答案偷傳進去。
- **輸出行為恰好三類**：`0`、`1`、`STOP`；`STOP` 是外部生成結束行為、不是螺旋語的一層/二層句號；停止後不再接回下一個輸出。
- 完整訓練 prefix = **當前教學 profile 下完整合法的 raw 題目 Q + 已生成的答案位元前綴**。不使用額外 `｜` 分隔。**句號尚未教導的初期**，由宿主在完整題目傳入後開始生成，模型只依固定短題格式學習；此時不能聲稱模型已從 raw 串自行辨識題答邊界。**句號正式教導後**，題目才要求合法句末 END，供模型學習其分句功能。teacher forcing 只提供**已有的正解前綴**而非未來 token；自主測試只接模型自己輸出。
- 不是模型憑空要猜目前 Q 是否已輸入完畢：外部宿主仍負責提供完整題目並呼叫模型生成；句號要由原生 bit 詞碼表示，不是將「何時呼叫模型」算作模型已習得的額外字元或已證明自主分題。嚴格分清「語法能力」與「宿主封包控制」。

## 三、特殊詞延後啟用：句號從 110 開始（最高優先級校正）

**作者補充（U，2026-11-12）**：特殊詞可以等資訊位長足夠、詞空間更寬裕才出現，這本身是可教的規則；初期不必預留低階句號。**原始 Q1–Q3 沒有句號，Q6 才示範句末 `110`。**

### 3.1 將「詞碼候選」和「已啟用的保留詞」分開

| 一層算符詞資訊階 n_op | 歷史句號碼模式 | 教學狀態 |
|---|---|---|
| 1 | `10`（若套公式可以寫出） | **未啟用、未保留**，不能宣稱它已是句號；n=1 原題 `01|00|10` 的 `10` 是合法資料詞 |
| 2 | `110` | **在句號課程啟用後才成為保留控制詞**；正式教材首度引入句號 |
| 3 | `1110` | 已有句號概念的後續升階按控制公式擴位 |
| 4 | `11110` | 同上 |
| n≥2 且 END 已啟用 | n 個 `1` + `0` | **不是全語言無條件佔位**；需看當前分支詞表與啟用狀態 |

原始論文 4.4 的表格可以列 `10` 為 n=1 的**候選句號碼**，但 Q1、Q2 實際把 `10` 當資料詞使用，句號到 Q6 的 `110` 才首次出現。**本實驗以具體教學題序定義「何時有此語義」，不能拿未啟用的候選碼提早擠掉資料。**

### 3.2 啟用／保留範圍與合法碰撞

1. 啟用前：`active_END=false`，出題器**不要求句尾 END，也不把 n=1 的 10 當已保留句號**。宿主仍在題目完整時啟動模型；這是外部時序，並非學生已學會自主分題。
2. 過渡期：升到 n_op=2 後，先學 `Echo=000`、`NegEcho=010`、`Zero=100`，然後新增 `END=110` 的**正式新詞課**。先保持其他能力不變，才能觀察句號是否成功學會。
3. 啟用後：控制/算符所在的**合法語法位置**必須保留 END 詞碼 `110`（升階改 `1110` 等）。不可把該控制碼分配給同一詞表分支的普通算符，也不可把任意資料詞恰好等於相同 bit 串視為自動句號：**語義依所在欄位與 profile 決定**。若特定初學教材選擇先避開這類資料值以減少混淆，必須標記為**教學篩選**而非宣稱螺旋語文法不允許。
4. 升階只進不退；舊概念不改 ID，只把資訊位擴到目前分支 n，END 則按已啟用的控制分支公式隨階擴位（`110→1110→11110`），不是將普通詞左補0。不同層 k 的降層詞（如二層 `1100`）另按其 profile 管理。
5. 原作者的 Q5、Q6：`01|100|010` → `000`（尚無句號）；`01|100|010|110` → `000`（正式加入句號）。這是**同一任務多了特殊控制詞**的理想受控教學配對。
6. 不可對 raw bitstream 全域禁用 `10`、`110` 或 `1110` 子字串；只在符合當前解析上下文的**完整詞界**上判定是否控制詞。輸出 `1110` 也可能是合法資料答案，STOP 仍是外部生成終止控制。
7. 出題器必須有 `active_END` 與分支級 `reserved_codes` 的 versioned grammar oracle，驗證 `parse(encode(AST,profile),profile)==AST`、未啟用的 END 不會偷偷被使用、啟用後 END 正確出現於其合法位置；不能假定所有位元串可憑尾零無上下文唯一解析。

### 3.3 不要一次測太多變因

句號何時加入，是教學設計的可測變因。可在後續單獨比較「n=2 一開始就教 END」與「先學三個算符再教 END」；但**不能**在同一組同時增加算符、資料階、句號和模型大小，再把結果歸因於某個詞。

## P030 補正：資料數字的升階只加一個高位，不重新分配詞碼（U 2026-11-12）

原作者更正：「**不會重編，例如算子數字只是多一位數**。」對普通數字/算子資料詞，升階的實質規則是保留原資訊值和原低位，**在高位增加一個資訊 bit**，並保留原本 `0^k` 尾碼。例如 k=1、值1：`10 → 010 → 0010`。舊概念的詞典 ID **不改、不另選新碼**；只因資訊寬度增加，bitstream 表示更長。新可用 ID 出現在新增高位所開的範圍。此處先前所有「重新編碼／重編碼」用語，應理解為**原有值的擴位表示**，不是重新分配任何普通數值或語義。

- **資料位數增長**與**算符詞典分支擴階**是兩件事。普通資料增長1位，不代表 Echo/NegEcho/其他算符同時要換詞碼。對每個分支記錄自己的 n、k、最高已分配 ID 和目前版本，不可任意批量重新分配 ID。
- **句號**是已啟用後依保留公式生成的特殊控制碼，例如一層 `110→1110`；這是控制詞的規律性擴位，不是普通數值的左補0，也不是任意改成另一個語義。早期 `10` 尚未啟用句號，仍可作資料。
- **動態成長網路的候選實驗**：當需支援的最大輸入長度增加1，增加1個輸入位置和1個隱藏神經元；新參數初始化，舊權重與 Adam 狀態保留。這是需要實驗的 A 組，不是已證明最優。加入等課程、固定寬度 B 組，與按學習瓶頸擴容 C 組；各組需記參數量、更新量和成本。
- **位置對齊很關鍵**：增加高位時舊低位應盡可能映到舊輸入位置（例如資料詞使用低位對齊），但完整 raw 句的句首、算符、句號及自回歸答案前綴可能因字數增加而位移；不能只保留權重就宣稱整句映射不變。若換用序列模型，需交代增長位置表示與權重移植如何實作。
- 原則仍是**升階不退回**。若需比較以原高位0表示的舊值，直接把同一值放進新寬度的題，不是回到舊詞典測試。這和長度固定詞界的教師提示是不同研究項目。

## 新增研究準則（U，2026-11-12）：擴容當下完整保留舊權重，訓練後量化其自然變化

作者明確要求：**不是在擴容時重排/重設舊權重，也不是永久凍結；升階擴容當下先完全保留所有舊權重與 Adam 狀態，再允許全模型繼續訓練，觀察各部分參數的自然變化。** 假設「原本的幾乎沒變」可能意味普通算子只擴大一個高位就能運作，但這是待驗假說，不可預設成立。特殊算符或跨位運算可能需要舊權重一起適應。

### 擴容的嚴格操作規則與功能檢查

1. 在第 t 次擴容前保存完整 `checkpoint_pre_expand`（權重、optimizer 的 moment/step、模型輸入位置映射、profile、詞表、RNG 狀態、測試案例）。擴容後逐一 assert：所有**既有權重逐元素完全相等**；Adam 既有狀態未被重設。不能以「功能差不多」取代參數等值驗證。
2. 新增一個資訊位對應一個新輸入位置及一個隱藏神經元（實驗 A）；**所有原有神經元仍與所有輸入相連**，新神經元也與所有輸入相連。額外新連線可隨機初始化，但擴容後的舊任務輸入須可明確映入新維度。若在舊概念上新增高位為 0，新輸入到舊神經元的連線即使隨機也不影響其輸入加權和；新增神經元到輸出層先可置零以避免未訓練前擾動舊函數，再開始共同更新。這是具體的**功能保持初始化候選**，而不是所有新權重一律隨機的唯一做法；務必報出哪些新參數設0，哪些隨機、為何。
3. 對齊位置映射不等於「改寫舊權重」。若使用固定位置 MLP，僅允許**無損對應舊連線/位置**；舊權重的數值必須原封不動。若輸入位位置移動，需要獨立記錄**權重陣列嵌入座標**和對應功能，不能以新參數索引不同誤報舊權重變動。完整題目的原始字串前綴可能變長，故即使保留舊連線數值也不保證整題函數不變，必須在升階前後用對應的等價舊任務測行為。
4. 擴容**當下、尚未進行任何梯度更新**，立即記錄舊任務/新位輸入的 free-run 答案、逐 token 誤差和 STOP；這能分清「擴容操作自己破壞能力」與「之後訓練改變能力」。
5. 然後**解除所有舊參數的凍結**，用同一組 optimizer 狀態繼續訓練。每個 checkpoint 記 `W_old_after - W_old_before` 的 per-layer L2、relative L2、max abs、變動百分比、梯度 norm、新增參數對輸出的貢獻；其中初始接近 0 的權重採絕對差，避免 relative ratio 無意義。最好另有舊功能保持率、各算符的增量成功率、未見新位測試、總更新/計算成本。
6. 事先分開選算符：`Echo`（直接拷貝）、`AND/OR/XOR`（逐位、共享規則有潛在增量性）、`NegEcho/Zero/One`（輸出長度/新增高位含義需配合）、`ADD`（若正式啟用，要測跨位進位）、`END/句號`（特殊保留控制詞公式及啟用時機）。**不要在論文/實作已未定義 ADD 時悄悄將它納入當前題庫**；可留作後續新算符實驗。
7. 用 A（每加1資訊位→加1神經元）對照 B（原網路固定寬度）、C（按學習瓶頸才擴容），另測「新增神經元輸出初始為0」和「所有新連線隨機」對功能保持的差異。相同合法教材、驗證閾值與 seeds，並對照擴容前後、訓練後舊權重變化與訓練花費。
8. **不能單憑舊權重變動很小就宣稱模組化擴位**：舊輸出可能已遭破壞，或新神經元重新學了大量舊功能；反過來，若任務因進位/資訊重排要求原有計算改變，較大的舊權重變化也不代表升階失敗。必須聯合看**舊功能保持、新能力、權重變化與總成本**。

作者主要假說：普通算子高位擴張時舊結構可能近似不變，新神經元學會新增高位；而跨位依賴的算符可能必須調整既有權重。**目的是觀察真實發生什麼，不是透過凍結舊權重讓結果看起來符合假說。**

## 四、增加模型容量，但保持三輸出與繼續訓練

P029 的 1171 參數 MLP 已處理單一 Echo 固定/逐階題，但新課程含多詞、可變長、跨算符與二層句法，**23個固定輸入槽不宜無規劃沿用**。本輪讓 Codex 在實跑前先評估兩個候選：

- 候選主模型：小型 causal Transformer，2層、d_model=32、4頭、FFN=128、最多32/48位上下文；token embedding 只有 0、1，output head 只有 0、1、STOP。最終精確參數量由實際程式列印（預估約數萬，不能用估計冒充精確）。
- 候選比較：相同輸入輸出限制的較小寬度（例如 d_model=24）或同參數量的簡單網路。**不強制必須 Transformer**；Codex 若提出 GRU/其他架構，先列出上下文承載、參數量、運算與訓練風險，再固定方案。不能因多一個模型選項就無限制掃參數/挑最好分數。
- **跨題、跨新算符、跨升階：維持同一學生權重及 optimizer 狀態**。從 P029 的 MLP 升級成新網路架構時，不能假裝能無損直接沿用其全部權重；可以**新建一個較大學生，從短題重新開始長期課程**，完整保留 P029 作歷史基準。若採知識移植/擴大舊層，需另外明文描述權重映射、遷移測試和新增參數初始化，不得冒稱完全沒有重新開始。
- 輸入長度原則：**優先限縮題目複雜度而不是增加資料位元數**。建議初期 `len(Q) <= 24 bits`，`len(Q)+len(answer_prefix) <= 32 bits`；後期二層若需長一點先算長度，明列超限題而非截斷。硬上限應由選定模型在 plan 中事前固定。
- 模型更新：每個正確 token 交叉熵、teacher forcing；每題無論答對答錯都換題；自由生成用自身前綴。必要的獎懲式對照可另立，不能偷換回「整題全對才換題」。

## 五、課程階段：句號延後加入，題型短而多樣

持續使用同一模型權重與 optimizer；不重新初始化。課程遵循原始題庫由容易到難的**功能啟用順序**。下面 `|` 只是人類檢查的人工詞界，不送入模型。

| 階段 | 教學目標 | 合法示例（Q → A，最後另輸出 STOP） | 注意事項 |
|---|---|---|---|
| 0 | 最短 Echo，**不教句號** | `01|00|00` → `00`；`01|00|10` → `10` | n_op=1；`10` 是合法資料，不是句號。模型依宿主開始生成的時序運作 |
| 1 | 資料詞逐階變長，算符仍 Echo | `01|00|010` → `010` | 原始 Q3 的資料升階；**不是**句號或算符升階 |
| 2 | 算符升階、NegEcho / Zero，**仍無句號** | `01|010|100` → `010`；`01|100|010` → `000` | n_op=2，保留本階可供新詞出現的空間 |
| 3 | **首次正式教句號 END=110** | `01|100|010|110` → `000` | 原始 Q6；啟用 `active_END=true`。資料與算符不變，觀察是否學會句界 |
| 4 | n_op=3：新算符、END 隨階擴位 | `01|1000|0010|1110` → `001`（CUT） | 純示例：CUT 去掉資料尾 0。Echo/Neg/Zero/END 等既有語義不改 ID，詞形按分支擴位公式成長，舊階不回退 |
| 5 | 雙運算元 AND，再增 OR/XOR | `01|1010|0010|1010|1110` → `0010` | n_op=3；需兩個資料詞，版本中同碼不同義的 OR/XOR 不可混用 |
| 6 | 二層類別、降層與短題 | `001|0000|1100|0100|0010|1110` → `0000`（Zero） | 需核對二層詞表、降層碼、各分支 n/k，仍只有 01 原始輸入 |
| 7 | 更多版本、新算符與有限長度複合題 | 由 grammar oracle 生成，勿手工猜詞碼 | 每次只新增少量功能，詞長增長受上下文上限限制 |

**第 4 階 CUT 範例中的 `0010` 是資料詞，輸出去掉其尾零為 `001`（3 bits），它不必再符合螺旋尾碼。** 先以原論文及 decoder 的 CUT 定義核對後才列正式題庫。最重要的是**先保持題目短、特殊詞逐階引入**，再加多運算元、二層和版本。

**符號碰撞診斷**：第 2 階「全寫1」若輸出碰巧等於 END，屬合法答案內容，不可被宿主直接截斷。第 3 階例中資料 `1010` 恰與 AND 算符碼相同，但出現在資料位置，因此可合法區分；這不是 END 衝突。**不要把資料和算符的同碼誤判成缺陷，也不能混用無角色資訊的詞典。**

**語法增長優先於訊息變長**：同樣 3/4-bit 資料詞，加入新操作、多資料詞與二層控制，比把資料擴到 8/16 bit 更能檢驗語言學習。若二層句長開始大於上限，先減少無必要封包/欄位或評估正規可擴上下文，不要偷偷刪句號或增加非原生分隔。

## 六、持續訓練策略、達標、對照

1. 同一學生完整連續學習；每題不論正誤都換，不卡在一題，教師按每個輸出位置提供標籤。**隨著算符新增，教材混入當前階的已知任務**，例如新任務70%、已知算符/語義30%（實跑前固定）；這不是回頭回教舊**詞階/舊裸碼**。如果作者要完全不複習已知任務，可另外做不複習分支對照。
2. 升階後**當階始終維持新 n**；歷史舊值不改 ID，只補足當前 n 的高位。若各分支 n 可不同，需維持 current_profile 的 k/n/offset 分支映射；不得在同一未標版本的 raw 流中切換舊 profile。
3. 所有題使用 grammar oracle；正式訓練/評估不得偷餵 oracle 的詞界、答案長度或算符標籤。教師可以計算正解作 CE loss，但模型不直接收到計算結果以外的提示。
4. 在每個階段的 **0/25/50/100/192/384/768/1536 題次**保存診斷指標，超過則再按固定間隔；避免只有 20,000 題終點分數。階段上限建議 3000 題/seed，實跑前可依負載一次調整並鎖定。太少題型時必須報 unique 題數，不能把100題曝光稱100個不同例子。
5. 初階有限全集可測全題；複雜階使用**事先分割**訓練、升階驗證和封存最終測試，避免反覆用最後測試選模型；每種操作及資料值不能只有單一樣本。建議階段通過標準：新階驗證完整回答 ≥95%，當階已學任務 ≥95%，STOP 正確時機 ≥99%，分開列每類失敗；連續3個**相隔有訓練**的檢查點達標。門檻是研究建議，實跑前凍結。
6. **核心遷移對照**：在關鍵節點（n=2→3、新算符、雙運算元、二層）保存持續訓練學生的 checkpoint，對照同一架構、同當前階題庫、從零初始化的新學生。分別記錄**進入新階後要新增多少題與 token 更新才達門檻**；另記先前成本，但本輪主要驗證新階適應優勢，不要求課程總成本最低。若沒有優勢或出現負遷移，照實報告。
7. 不因較大模型過關就宣稱神經網路已「理解完整螺旋語」；需區分 Echo 模式、算符語義、句號判讀、升階/升層、版本識別與未見組合泛化；外部 grammar oracle 的能力不能算在學生頭上。
8. 句號學習的獨立驗證：同樣前綴題型但不同資料、不同 END 階數；打亂無關位置，檢查模型是否仍於合法問句末尾後回答；設非法題/缺 END 測試**由宿主拒題**而非假稱學生自行有 parser。將來再單獨測無宿主控制的連續對話收發。

## 六之一、同級神經網路 × 純翻譯解析器：通用輸出競賽（U 修正，2026-11-12）

### 命題與重要更正

作者說：「**解析器只是幫忙翻譯而已，如果是比賽的話，那得教模型怎麼再把輸出格式弄成通用的。**」本節**取代**上一版將 parser/executor 混為一談、把「學生只要選工具/算符，執行交給外部程式」當成核心任務的寫法。真正要比較的是**同級神經網路自己學會的操作能力與輸出能力**，解析器只做語法表示的可逆/無損轉換與合法性檢查，**不替模型執行 AND、OR、XOR、算術或其他答案計算，不選算符、不推理、不提示答案**。

### 任務與翻譯介面

1. 建立一份中立的任務 AST/語義規格作為出題與評分標準；題目的答案由**離線教師 oracle** 產出供標籤/驗證，**不在學生推理路徑**中作任何計算或提示。
2. S：學生使用螺旋語輸入（0/1 bitstream，按 profile 切詞）；F：學生使用其他明確規範的平面編碼；可增 H：非螺旋的階層編碼。各組模型的參數量、寬度成長規則、總訓練成本、學習課程、操作集合及 seed 設計公平對照。
3. **解析器只能做翻譯**：如 token/詞界/階層/詞表 ID 的語法轉換、模型原生答案到共通答案格式的編碼轉換，以及合法性檢查；不得計算題目的結果。如譯碼已產生運算結果、提取目標答案、替模型選算符，該組實驗無效。若使用 parser 先把雙方題目都轉成完全相同的 AST 再餵學生，會把「語言表示差異」從模型輸入中抹掉，不能拿來驗證螺旋語表示優勢；可另列純 AST 控制組。
4. 固定**通用答案格式**，例如二進位標準值加 `STOP`。若不同任務答案位長不一，應事先定義共同可學的長度/型別編碼（或有明確適用範圍的固定輸出寬度）；不能靠評分器自動猜答案長度、隱藏補零、或容忍只對某組的別名。模型只有輸出 `0、1、STOP`，通用輸出不得偷偷追加特殊字元。

### 分兩種模式，檢查模型是否真的學會輸出

- **模式 A｜母語回答、翻譯評分**：S 用螺旋語答案、F 用其原生答案，兩方模型**必須自己計算結果**。純翻譯器把各自輸出轉換成相同標準答案，再由評分器判定。測試「語言是否幫助模型更容易學到操作規律」，不是測格式轉換學習。
- **模式 B｜同一通用輸出**：S/F/H 各自讀自己的輸入語言，但**所有模型直接學習輸出相同的通用二進位答案＋STOP**。通用格式轉換本身也是學生要學的能力，不能交給 parser 偷做；要把新增的格式教學成本計入總成本。這才是作者說的正式比賽模式。
- **模式 C（可選）｜輸入和輸出逐項拆解**：同一模型再比較「只學操作」「只學翻譯」「兩者都學」，量化通用輸出課程究竟增加多少學習成本以及是否有負遷移；保證沒有拿 oracle 輸出直接回填模型。

### 評分、公平性、成果判準

- 完整能力數：每種算符必須在事前保留的未見題/反例達預定成功率，才計一項；另列未見組合泛化、保留率、新增一個資訊位或一個算符的增量學習題數。
- 預算：同等神經網路參數量和更新 FLOPs 下的能力數，及相同累積訓練+傳輸+解析總資源下的能力；同時報 parser 本身程式碼與翻譯費用。不因它「只是翻譯」就把成本當成零，也不把 parser 的功能當成學生的本領。
- 針對短題、長題、混合詞長和通用格式難度預先分組，控制資料量與模型輸入上下文；如某組原生編碼較短，那可能正是語言設計的真實優勢，需同時給出「同題次」和「同總 bit/token/FLOPs」兩種基準。
- **模型能力 ≠ 表達能力 ≠ 翻譯器能力**：要清楚回報是「SLE 模型本身會的更多」、「SLE+翻譯器系統比較省」還是「SLE 在同一通用輸出下泛化更好」，不可相互替換。
- 初期可先實測 2–3 個算符、短數字和一種通用答案格式，待流程穩定再擴展；不得一開始就拿多層、長鏈、版本與任意自由長度全部混合。
- 若 S 在多 seed、固定預算和通用輸出模式下，持續穩定掌握更多操作／更快適應新位，且排除了翻譯器運算代答，就能構成可驗證的研究結果；其學術新穎性另需比對既有研究。

**[更新]** 解析器僅做表示翻譯；正式比賽要讓學生自己學通用答案格式。
**[取代]** 上一版「每邊都有 parser/executor、模型只選工具，工具計算答案」的假設。
**[原因]** 這會把外部程式能力錯誤算進神經網路，並漏掉共通輸出格式的訓練成本。
**[狀態]** 教學規格已修正，信心高；尚未做正式受控對照實驗。

### P030 補充｜後接獨立轉換神經網路（U，2026-11-12）

作者提出：**在螺旋語主學生後面接一個獨立的「轉換神經網路」，使主學生只學運算與螺旋語，轉換網路負責把主學生原生答案轉成比賽所需的 ASCII 或通用格式。** 這是研究方案，並非已實測成果。此方案與上面的「模式 B：由主模型直接學通用輸出」是**兩種可並列比較的模式**，不能把模式 B 當成參賽必要條件。

- **模式 D｜分離式神經轉碼**：螺旋語主模型 `0/1 → 原生螺旋語答案/STOP` → 獨立的轉碼神經網路 `原生答案(+必要的明示profile) → 通用答案ASCII/二進位格式`。主模型不必為學 ASCII 再挪出主要容量。對照組的主模型也可接各自**只做格式轉換**的小網路，或全部使用相同規格的外部固定轉碼器另報成績。
- 優先採**兩段式訓練**：固定已訓練的主學生，獨立用配對碼流訓練轉碼器；之後可再研究聯合微調，但不得把聯合微調的收益說成純隔離轉碼訓練成果。建立已知原生碼→通用碼之間的 unseen 長度、未知數值/組合、句號/STOP 與版本泛化測試。
- 轉碼器**不准運算原始題目或代替主學生求解**：只讀模型已產生的答案與可公開的格式協議資訊，不可讀題目原文、教師正解、答案 oracle 或隱藏解題標籤。若需 version/profile 提示，兩組需同等提供並計入傳輸/狀態成本。
- ASCII 轉換對固定類型的 bit 碼確實可以由純確定性程式完成；但作者此處的研究目標是**可學習、可共用、可接續擴充的神經轉碼模組**。記錄「硬編碼解析器 / 小轉碼神經網路 / 主學生直接輸出通用格式」三者，不能為了製造神經轉碼優勢隱瞞固定轉碼的低成本基線。
- 公平性給出**兩套可讀成績**：①相同**主模型**參數量時，學會的運算能力數與泛化；②相同**總參數**（主學生+轉碼器）、總訓練 FLOPs、推論 FLOPs、RAM、轉碼訓練樣本及通訊成本時，通用格式端到端能力。不能用主模型參數來冒充整套系統參數。
- 若轉碼器在不同主學生/不同語言版本間重複使用，需單獨記錄它首次訓練成本、每次使用成本與重訓成本；可另外比較單模型/多模型共享攤提後的總成本。共用轉碼器若需認識不同語言版本，不得把跨版查表成本忽略。

**[更新]** 通用答案不必主模型親自學；可用後接且獨立訓練的神經網路翻譯。
**[取代]** 「正式比賽必須由主模型直接輸出 ASCII/共同格式」的過度限制；保留其作為直接輸出的對照組。
**[原因]** 計算能力與輸出格式轉換是可模組化拆開的能力。
**[狀態]** 可行設計，尚未實測；公平對照需報主模型與整體系統兩種預算。

## 六之二、n=4「11110」升階儀式：能否促進小網路有效重組？（作者假說 U，2026-11-12）

作者提出：「升階也許可以用誇張點的儀式，算子變成11110（多了一位而且是句號），題型不管是什麼，回答跟著11110，這樣就變成儀式了，期待網路能自己大幅更新？」這是**待驗證的訓練干預假說**，不能寫成已產生權重重組或神經湧現的結果。

### 假說的確切邊界
- 在**n=4 的同一 SLE 語法分支**，前階 END 如 n=3 的 `1110` 可擴位為 `11110`。新詞形「多一個1」能成為顯著的升階提示，但這仍是有上下文的詞：必須明確指定 `k,n,offset,version,role`，不能把任意 bit 子字串 `11110` 當全球無條件 END。
- 作者構想的**儀式題**：從 Echo、NegEcho、AND、ADD 等不同舊題型取樣，把該輪的「算子」切為 `11110`，期待學生不論題材都輸出 `11110`（生成動作末尾仍是 `STOP`）。這些是**控制／確認升階**的題，不是原題數學運算仍然正確。不要把儀式時回答 `11110` 當作數學技能成功率。
- **語法角色衝突一定要顯式定義**：`11110` 如果在一般 profile 已被指定為句號，就不能默默又當一般數學算符。建議在**獨立的升階儀式 frame / profile / 操作槽解釋**中賦予它「停止常規題型、回應同一控制詞」的語義；原一般題仍將它解釋為 END，儀式模式和一般模式不應相互污染。切詞/解析器應可 round-trip，且學生不得獲得隱藏 task label（只能由合法的 SLE 訊號區別）。
- 進入儀式前**不得重設或凍結全部舊權重**；若同步升階增加神經元，新增時原權重與 Adam 狀態必須保持完整（沿用之前決定），儀式期間正常反向傳播且追蹤舊權重**自然改變**。儀式不是只有在推論時展示標記就能自動修改固定權重；必須有實際訓練/在線更新流程。
- **不能把全題都變同一答案當成自動獲得深層重組**：恆定標籤容易使學生忽視任務輸入，或僅快速學會新句號的輸出偏置。開始時大 gradient 也不代表數學泛化變好；重複到 loss 很低後反而沒有足夠學習訊號。可能帶來災難性遺忘。

### 最小可復現對照設計（A）
在完全相同的 n=3 已訓練 checkpoint、擴到 n=4 的新增參數、總更新數、位元曝光、optimizer、資料與 seeds 下，做短小的升階干預：
- **R0｜無儀式**：正常直接開始 n=4 數學題，作基準。
- **R1｜11110 儀式**：固定若干題（不同既有題型，等時段）全部以合法 SLE 儀式 frame 呈現、答案 `11110`；隨即進入正常 n=4 數學題。
- **R2｜普通升階提示**：傳送版本/階層變化與通常新格式示例，但**不**用全部答案同一詞。比較大動作的儀式是否比自然教學有效。
- **R3｜等量固定答案控制**：合法且同題次的控制詞（非新階 END），讓答案都相同，檢驗效果是否只因「大量簡單重複標籤」，而不是 `11110` 的升階結構。
- 額外可加入 **R4｜短儀式與正常數學題交替**，觀察是否減少對舊題型的遺忘；對「升階不退回」的原課程要求，這裡**不回去教舊詞階**，但可以用新 n=4 編碼呈現已學的算符語義，避免混同舊詞階退回。

### 要測「自己大幅更新」，不能只看權重變動幅度
- 儀式前 / 儀式後立即 / n=4 正常數學訓練後：逐層原權重 `L2`、相對/絕對差、gradient norm、activation/表示相似度、輸出偏置變化，以及**新神經元是否真正被使用**（而不只是 output 頭權重被拉高）。
- 在同樣未見新高位數與未見運算組合中測數學正確率、達標題數/更新 FLOPs、舊算符語義保留率；另報**升階標記辨識率**。把「辨識儀式」「權重劇烈漂移」「真正數學能力改善」做三張獨立成績。
- 必須檢驗儀式的**短期副作用**（所有正常題都輸出 `11110` 的比例）、恢復所需更新數，並保留多 seed。若 R1 只有更大的參數變動、沒有更快學到 n=4 且舊能力減退，就應明確判定儀式對數學學習無益。
- 若觀察到未見題準確率突然躍升，可與小模型模算術研究中 **grokking** 的遲滯泛化現象類比，但**不能僅因升階或權重幅度大就稱 grokking**。參考：https://pair.withgoogle.com/explorables/grokking/ （訓練和測試能力可能在後期急遽分離）；https://research.google/pubs/multitask-learning-via-interleaving-a-neural-network-investigation/ （切換與交錯教學可能改善/破壞記憶，需實證）。

### 與共用 SLE 題庫的關係
- P031 的共用題庫可新增 `frame_kind=upgrade_ritual`、`source_operator_family`、`upgrade_from_n=3`、`upgrade_to_n=4`、`ritual_control_bits=11110`、`is_math_gradeable=false`、`expected_response_bits=11110`、`result_stop=STOP` 等教師 manifest 欄位。**除了合法 SLE framing，這些訓練用標籤不可直送學生模型**。
- 倉鼠 VM 和神經網路可以共用該儀式詞的語法與解釋；但這個假說核心是**NN 的權重更新**，VM 如果接受儀式也要自訂可比的「狀態更新」定義，不能把 VM 的可寫記憶或演化叫作梯度更新。
- 初次可以只作一個小型 toy 實驗，先經原始 profile oracle 確認 `11110` 的角色、合法性，**不必等待完整國高中題庫**；若語法無法無歧義容納，先標 `syntax-pending`，勿硬塞到已存在正常數學語法。

**[更新]** 升階時增加「不同題型共同回覆 `11110`」的儀式干預，觀察是否觸發更大且**有用**的網路更新。
**[取代]** 單純假定增加1 bit/1 神經元後直接正常訓練已涵蓋所有升階教法的想法；原正常路線仍為控制組。

**[狀態]** 未驗證創新實驗假說，能否促進遷移信心低；合法控制詞設計與可重播實測待完成。
