## 1. 現有實測（F/T 屬 Codex 原報告；此文件僅查閱，不冒稱本輪重跑）

P030 實驗是純 `0/1` 輸入、`0/1/STOP` 輸出；Echo → NegEcho → Zero → END；三 seeds 101/202/303。

- 動態方案從 L8/H64/1,283 參數長到 L13/H69/2,073 參數，三組都停在加入 NegEcho。
- 固定容量 L16/H72/2,595 參數，一組 fixed303 到 END 並在驗證全對，但其未見測試只有1/3正確，其餘固定組也卡在 NegEcho。
- 三組動態網路：相同 Echo 驗證題 `Q=010001010`，加入 NegEcho 前 free-run `1010S`，加入後 `1000S`；**已教 Echo/Neg 值仍然6/6+6/6**。有具體的舊未見規律受到干擾，而不是模型沒接上。
- 原 split：對 n3 每算符 `train=[0,1,2,3,4,7]`、val=5、test=6，**單個 val/test 數值太少**，不足以判斷一般化效果；n1/n2 全集訓練，不能拿這些當未見泛化。
- 固定容量在最初即有更多參數，和動態容量的總 FLOPs/初始化歷史不同，現有結果不能據此認定單純放大一定有效。

## 2. 下一步不是盲目堆參數，先進行診斷

P032-D：僅用 P030 已存 checkpoints（須先檢查實際載入可行性），**不改權重**，把 n3 所有8個合法值在 Echo、NegEcho、Zero 下的答案、自由生成、teacher-forcing 正確率、STOP 位置、logits/confidence、距離等報成完整真值表（記 input/Q、合法 profile、stage）。把輸入位形與答錯位對齊，檢查錯誤是否集中在 `value=5/6`、新高位、特定算符或 STOP。不能將原本 val/test 題重新命名為全新盲題。

**要將「沒見過數值」和「升階後位置移動」分開**；n3 的位值、算符位置、句號是否啟用都要獨立標記。尤其 input left-alignment 會使某些位的**整串絕對位置**因 op_n/資料寬度變化而平移；原權重形狀保留不自動代表值位規律保留。

## 3. P032-A：容量 H × 新舊題比例 2×2 受控訓練

只考察 Echo→加入 NegEcho 的關鍵關卡，**目前不再加 Zero/ONE/AND，也不進 n4/國小加法**，免得同時引入太多失敗來源。沿用 P030 的 SLE 合法 raw 01 語法、輸出規則、Adam/狀態延續和 teacher-forcing，**避免本輪先偷改網路表示、外加 task/answer length oracle**。

| 分組 | 固定 L | hidden H | 加 NegEcho 後新：舊題比例 |
|---|---:|---:|---|
| A0 | 16 | 72 | 70:30 |
| A1 | 16 | 128 | 70:30 |
| A2 | 16 | 72 | 50:50 |
| A3 | 16 | 128 | 50:50 |

- L16/H72 參數 `(2L+4)*H+3=2595`；L16/H128 為 **4,611**。更大容量不預設較優；若兩組都卡住，後續才考慮 H256 / 結構變更，不用預先堆到百萬參數。
- 初始擴容時保留舊 block、Adam m/v 與原參數 birth，新增神經元輸出可初始化為0以保留共同短題功能；要保證**學完舊題之前的相同初始函數**，並報新增參數數量。從相同階段 checkpoint 生長可做另一個 growth ablation；**不能把「固定 H128 從一開始有」與「到 Neg 時才增長」混稱容量純效果**。
- 每個容量/教學比例使用相同 seed（最少101/202/303）、相同題目順序的可比規則、相同每階題次與 optimizer 參數、輸入編碼、loss 和總 token updates。注意不同新舊配比本來會造成實收樣本不同；同時報每算符 exposure，不能只比較總題數。
- 第一輪事先固定**至少2組不同的 n3 保留值分割**，每組仍是6 train/1 val/1 test（8值全數有位置），避免只靠 P030 `val=5/test=6` 導致結果偏差；分割必須在訓練前決定，不得看成績後選好看的保留題。每組 2x2x3 seeds，兩組 split 總24條受控訓練；若計算負荷高先完成一組分割，保留另一組作預先登記複驗，不得宣稱已跑兩組。
- 若使用 P030 已曝光的 `val=5,test=6` 做診斷，報為「重用診斷集」；新 P032 正式測試應使用新產生/預先保留的 split 並記錄固定 manifest。所有訓練 split、model init、取樣 seed、max_updates 在真正執行前寫入 manifest。
- 每階至多3000題（可保留P030停準則作主分析），對比相同題次下固定測點，**不能只選成功時刻**；即使某組提前達標，也需事前明定等預算比較方式（例如評估於同一累積題次的快照）以免停時不同造成偏差。
- 分別報同題次與同計算 FLOPs（增加 H 必須計入較高計算成本）；輸入總 bits、教師標籤 bits、模型參數+optimizer記憶體、train/infer MAC、walltime；只量 dense MAC 時仍不得冒稱硬體總 FLOPs。

## 4. 評量：分清記住、泛化、保留、成本

- 主要：每算符完整 free-run 正確率（本輪 n3 8 值皆列明 train/val/test，聚合時明確避開將 train 稱未教）、不同 split/seed 的中位數及最差結果；記答案逐位正確率、STOP 正確率。
- 保留：Echo 在加入 Neg 前後**相同合法 raw Q**的輸出逐題配對；已教/未教資料分列，不把舊輸入形狀變更混作遺忘。
- 學習：達到預先固定未見題門檻所需題次、全 run 達標數；如果只是 train 12/12 但未見題不改善，明確判定不算成功泛化。
- 成長：H72 與 H128 的同歷史舊權重/Adam 狀態、升階前後的權重 L2 / 相對漂移 / gradient / 新 hidden contribution；**大幅權重更新 ≠ 有用重組**。不需先做 `11110` 儀式；它是之後單獨受控實驗，不應混進容量主試驗。
- 預先判準：若 H128 在多 seed、多分割下泛化提升而舊 Echo 保持相近，才支持「容量是瓶頸」；若改比例才有效，先修教學；若兩者都差，優先檢查**表示/位置、訓練目標、極小題庫**，而非無限加網路。

## 5. P032-B：只有在容量/課程檢查後再試「增長策略」

在最有希望的 P032-A 學生上，比較：
- B0：較大 H 從最初就固定。
- B1：先以 H72 學舊階，加入 Neg 時保留全部已學權重/Adam，擴至 H128。
- B2：H72 不增長（繼續學同樣課程）。

配對相同開始模型與訓練課程，報訓練成本與老技能保留。「模型變大」和「模型何時變大」是**兩個不同問題**，不要只看擴容當下舊 logits 完全相同，就宣稱擴容學習比較好。
