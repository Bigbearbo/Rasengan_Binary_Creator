# 螺旋語（Spiral Language Encoding, SLE）與 ICFP 2020 外星語言：比較、研究現況與 Codex 交接

> 狀態：研究導覽與工程交接，**不是**兩套語言性能優劣的定論，也不是最新的完整 SLE 正式規格。  
> 編寫日期：2026-11-11。對照目標限定為 **ICFP Programming Contest 2020 / Message From Space**，不是 2024 年另行設計的「ICFP language」。  
> 作者／概念來源：Bigbearbo 的螺旋語與倉鼠世界構想；比較框架與實驗注意事項由 AI 協助整理。須保留這項來源區分。

## 1. 先讀結論

**ICFP 2020** 是以外星訊息逐步揭露的、可執行的函數式語言／互動協議：數學、`ap` 函數應用、組合子、`cons/nil`、列表、modulation、Galaxy 等。其核心功能是「描述與執行計算」，教學材料示範如何由未知訊息逐步認出規則。

**SLE** 是研究中的階層化、可擴階的二進位語詞與協議架構：透過版本／語法樹／詞表保存解析上下文，允許先教簡單詞，再增量新增詞義、題庫與訊息格式；研究目標包括小型 AI 通訊、記憶、可執行知識傳授與跨版本互通。

兩者不是「一個會計算，另一個不會」，也不是「ICFP 無法擴充」：**ICFP 可以藉函數與列表組合新能力；SLE 希望更直接管理語言本身的詞表、層階、教學與演化。** 應在相同任務下量測建構、維護與交換成本，不能依宣傳或語法外觀判勝負。

## 2. ICFP 2020：不要混淆三個層面

| 層面 | 2020 實際內容 | 比較時注意 |
| --- | --- | --- |
| 外星訊息／教學序列 | 42 則循序消息：數字、相等、加減乘除、布林、函數、列表、繪圖到互動 | 這是給人類參賽者破解的材料，不等於已有從零神經網路學習實驗 |
| 表達／執行語言 | `ap f x` 表示函數應用；`ap ap add 2 3` 計算 5；組合子、變數、列表與遞迴可組合複雜程式 | 是有力的計算基準；不能說它「只能兩個參數」或「沒巢狀」 |
| 二進位 modulation | 將數字及 `cons/nil` 資料編碼成線性位元串；`00` 是 nil、`01/10` 是非負／負數、`11` 是 pair 的型別起始（整數另有長度編碼） | **不是**把圖形語言中的每個 `ap/add` 詞直接當作固定二進位詞表；不要把兩種語法混為一談 |

可核對範例：

```text
ap inc 0           => 1
ap ap add 2 3      => 5
ap ap add 2 ap ap add 3 4  => 9
```

語法的可學習演示，和一個固定權重、原本不懂語言的小型 AI 能否習得，是**不同的證據等級**。參賽隊伍主要是人類解碼、編寫 parser/VM/GUI/代理程式。

## 3. SLE 的核心與已知解析前提

本倉庫的早期定義（另參見 `spiral_language.md`、`README.md`）以以下形式表示螺旋詞：

```text
word = information_bits(n) + zero_suffix(k)
S = w[1] ... w[n] 0^k
Tokenize(S, k, n, offset)
```

`k` 是層數、`n` 是資訊位長，`offset` 是目前詞起始位置。**必須有正確的層級、詞長和起點**，才有明確的局部切詞結果；單看一串任意 0/1 不保證能憑尾零唯一還原全句。現有協議研究用初始化碼、詞表／版本上下文與外部解析器來提供必要資訊。若採其他編碼變體，需重新聲明規則。

SLE 的研究方向不只一種：  
**A. 分層、各分支獨立擴階**：不同層／領域的詞長可按需要更新；  
**B. 全域等長概念詞典（競爭方案）**：同版本全部用固定 `N`，碼空間不足時整體升級；  
**C. 可研究混合方案**：高頻概念專用詞碼，複雜概念以函式／列表／語義描述組成。

**A/B 都是需要公平測試的方案，不要讓 Codex 自行宣告某一方案是唯一正統。** 句號長度、詞階更新、作用域、同義詞、命名、語義包、引用與語境錨點等也存在版本或研究提案；不得把舊範例的單一詞表硬寫成永久規格。

示意輸入（僅描述結構，**不是**宣稱這行逗號文字是實際線上位元）：

```text
數學 / 新算符5 / 參數1 / 參數2
```

解析器在既有詞階／欄位規格下可以確定「數學」「算符 5」「參數 1、2」的位置，提示 AI「算符 5 未知」；**它沒有因此知道算符 5 是加法**。語義仍要從例題、教學、驗證或可執行定義取得。

## 4. 比較表：優勢、代價、限制

| 維度 | ICFP 2020 | 螺旋語 SLE | 真正需要驗證 |
| --- | --- | --- | --- |
| 設計中心 | 函數式求值、組合子、資料/互動 | 層階詞典、協議與學習/記憶共同擴展 | 是否能在同樣算力、教材下更有效達成任務 |
| 解析 | 符號語言要有 parser；modulation 可解資料位元流 | 在已知 `k/n/offset` 與版本下按詞階切分 | 未知版本啟動、錯誤後恢復、輸入位元／CPU |
| 組合與巢狀 | `ap`、部分應用、組合子、`cons`、列表、函數 | 可用層級、巢狀、概念詞及／或可執行指令 | 不可低估 ICFP，也不能把 SLE 的設計當成完成 |
| 新功能 | 可新增函數／列表表示，不必更改 modulation 的原生型別 | 可增詞、增階、增層、更新詞表與版本 | 兩端都給同樣擴充權限後，誰的遷移成本較低 |
| 新舊相容 | 函式定義和封裝可維持相容；修改底層編碼仍需協調 | 透過 profile/詞表版本重編碼與舊版保留 | 同名改義、作用域、依賴與舊訊息重播 |
| 教不懂自然語言的 AI | 42 則教學消息可當教材；原競賽不是神經網路習得證明 | 題庫＋外部解析器＋語法樹可逐步提示未知詞 | 固定權重小模型能否依例子學會未知語義 |
| 記憶／知識包 | 可用函數、列表、狀態與外部協議包裝 | 研究中已做樹快照、增量包及題庫狀態原型 | 端到端記憶/語義移植及可執行安全驗收 |
| 災難性遺忘 | 外部規則可保存；神經網路遺忘仍另論 | 外部樹與程式可留住知識，但模型權重仍可能遺忘 | 舊任務保持率、檢索失敗率、總資源成本 |
| 效率 | 有成熟可執行基線，但任務依實作而異 | 尚無跨語言同題公平測量的總成本優勢 | bits、CPU、RAM、儲存、回合數、更新成本 |

**不要說**「SLE 天然消除災難性遺忘」或「ICFP 不會擴展」。螺旋語可以把記憶儲存與神經網路權重分離，但「資料還在」不代表「學生一定找得到且會使用」。

## 5. SLE 解析器雙代理實驗：目前有什麼，沒有什麼

此段以 2026-11-03 的 **腳本化代理實驗記錄**作為來源；原始 ZIP／逐位元證據保存在 ChatGPT 圖書館的研究資料夾，**不代表目前已在此 Git 倉庫內**。Codex 若在本 repo 找不到對應檔案，必須先要求或取得原始封存，不可臆造測試通過。

| 版本 | 當時的原型進展 | 證據界限 |
| --- | --- | --- |
| v0.1 | 基本切詞、樹狀態、未知算符提示、錯誤回報；雙向題例 | 預定欄位與候選算符；腳本化 |
| v0.2 | CONFIG、詞長／版本更新、舊算符回編碼與保留 | 不代表能從任意無共識位元流自行解碼 |
| v0.3 | 題庫也是解析器狀態：從簡單出題、回饋、複習、JSON 斷點續學 | 課程流程演示，不是神經網路已學會 |
| v0.4 | 全樹語法包，分包／校驗／缺包重傳／原子套用；不覆寫學生私人題庫 | 整樹的效能不一定比一般 JSON 有利 |
| v0.5 | 增量語法包；算符最大編號 17→31→32，資訊位長 5→5→6；舊版詞碼可解 | 原型只處理已知版本與部分詞典；仍有舊標頭長度上限 |
| v0.6 | **修正最大編號儲存位置**：高水位應存於樹內的算符分支節點，而非樹外 registry | 當時腳本化原型測試紀錄；未證實真實模型習得 |

### 高水位（high-water mark）不可忘

使用者的工程要求是：**解析器的語法樹節點要保存每個分支最高「已分配」編號**。這不是 ChatGPT 的記憶、也不是僅存在別的 `operator_registry` 的變數。

```json
{
  "tree": {
    "math": {
      "operator_branch": {"highwater": 32},
      "operators": {
        "5": {"status": "confirmed", "meaning": "add"},
        "17": {"status": "confirmed", "meaning": "or"}
      }
    }
  }
}
```

- `highwater` 不等於現存節點數、不等於現存最大 ID。刪除或停用節點後仍不得退回已分配碼。
- 最小資訊位長：`n_min = max(1, highwater.bit_length())`（非負整數編號的此原型約定）。**實際詞碼還要以當前版本 profile 的 `n/k` 編碼**。
- 原型示例：在 `k=2` 時，算符 5 在 v2 的詞碼為 `0010100`（5-bit 資訊＋`00`）；擴到 v3/n6 後是 `00010100`。同一 ID 可有不同版本的碼；舊版 profile 必須保留才能正確解舊封包。
- 若傳整樹或增量包，連同分支高水位、版本 profile、節點定義一起同步；接收端先驗證後**原子更新**，不得先套部分資料再發現衝突。
- 既存 v0.5 的樹外 `operator_registry` 只可作**遷移輸入**，不應繼續作正規儲存位置。

### 不要混同三種學習

1. 2020 ICFP：人類參賽者藉外星訊息破解語言與實作 VM。
2. 2026-11 的純 01 跨模型教學：已有自然語言預訓練的大模型，在訊息限制下依例題部分學習；不是從零模型。
3. SLE v0.1～v0.6：**腳本化**教師與學生，驗證解析器、樹、題庫和傳輸流程；不是神經網路習得實測。

## 6. Codex 的建議任務：先研究對照，再寫程式

建議先以本 repo 的 `spiral_language.md` 和初版 C++ 作歷史參考，但不要將 2025 年檔案當作 2026 年實驗的最新程式。沒有實際原始 ZIP 時，不應改動倉鼠 VM 或編造比較分數。

**第一輪／規格核對：**
1. 確認要比較 SLE A（分層）或 B（全域等長），寫出 `bootstrap`、`k/n/offset`、句界／巢狀、版本和作用域約定；對 ICFP 同時提供 symbolic parser 與 modulation codec。
2. 整理等價抽象語法樹（AST）任務集；同一任務以兩套語法編碼，不要故意給一邊過度簡化、另一邊大量包裝。
3. 驗證 `parse(encode(AST)) == AST`、解析／格式錯誤時資料不污染、舊版回放、同名不同定義不靜默串用。

**第二輪／可比較的功能工作負載：**
1. 5/100 項加法；`add`/ `mul` 混合與多層巢狀；`cons` 列表、`nil`、列表操作。
2. 加一個新算符和多個同義詞；再加入新領域、巢狀作用域、版本改動；最後刪停一個節點、驗證 `highwater` 不下降。
3. 完整語法樹傳送 → 增量分支傳送 → 中斷／損毀重傳 → 恢復後重新載入狀態。
4. 對兩套語言分別測「只新增函式」及「修改底層詞碼」；**權限和功能要對等**。

**第三輪／學習而非硬編答案：**
1. 同一個固定權重的學生模型分別面對 SLE、ICFP 與普通表格/API 對照；教師從簡入難。
2. 檢查未知詞定位、要求示例、真實未見題泛化、舊題複習和斷點載入。若學生已有候選函式庫，記錄這個先驗。
3. 記錄題目／答案是否被先行洩漏、教師是否在各輪改了規則、是否只有模仿位元模式。

**至少輸出以下指標**：資料傳輸 bits（區分 payload 與重傳／控制）、CPU 時間、RAM／樹容量、詞表增量大小、學習所需例題數與回合數、錯誤恢復率、舊任務正確率，以及跨版本改動成本。另提供反例與失敗樣本，不要只報 PASS。

## 7. 開發守則（給 Codex）

- **先讀既有原始碼及測試，再修改。** 只對真正可取得的程式碼宣稱「已驗證」；報告中區分 U（作者原始設計）、F（檔案／原典）、T（可重播實測）、A（AI 推論／候選）、H（歷史版本）。
- 確保實驗可擴充到更大的題庫、語法樹與多代理；勿為小樣本短期速度犧牲正確性或漸進擴展。
- 無合法版本／必要詞表時應回報缺件，**不要把猜測寫入正式語法樹**；候選解析先隔離。
- 發現新詞碼不代表理解詞義；函數名稱不等於可安全執行的程式。可執行知識移植要另做依賴、權限與資源限制檢查。
- 比較 SLE 與 ICFP 時允許兩邊互相吸收功能，不把任何一邊宣傳成先天優勝者。需要辨別「競賽時固定語言」與「可持續維護的擴充協議」。
- 每次修改提交**變更清單、測試命令、測試結果、未完成項目**。勿覆寫既有實驗史，新增版本需保留來源追蹤。
- **不要混用 ICFP 2024 的 base-94 語言**（`I`/`S`/`B` 等 token）和 ICFP 2020 的 Message From Space。
