## 用語原則

語詞不以單字、雙字或固定字數為前提。可使用熟悉的自然語言組合表達一個概念，不刻意造暗號。同義詞可以存在，**但當詞義在來源、時間或證據層級有差別時，不把它們當成完全同義**。新組合先讓 AI 按詞義與前後文理解，不急著加入正式詞典；若跨句重用頻繁且含義穩定，再給它一個可追蹤的詞義定義。句號和語境切換可以承擔作用域，但不能把 AI 猜出的隱含詞冒充使用者原本寫出的詞。

## 本輪偏好的核心概念詞

| 優先詞 | 核心意思 | 必須保留的區別 |
|---|---|---|
| `領域` | 後續敘述的研究主題／專案 | 同一名稱不同專案不可默默混讀 |
| `語境` | 詞義、版本、時間及局部作用域 | 只有日期不等於完整定義快照 |
| `句號` | 依當前共識終止句子或局部作用域 | 有歧義時不可憑單字自行決定精確邊界 |
| `原話` | 逐字來源材料 | 不等於 AI 的重述 |
| `AI解讀` | 模型對原話的解釋 | 不能回填成作者原意或已證實事件 |
| `記錄` | 保存待查內容或事件 | 記下來不等於已驗證 |
| `來源` | 原稿／報告／實驗紀錄及其位置版本 | 名稱不保證內容未變，要追蹤版本 |
| `來源記載` | 某資料**聲稱或記錄**的內容 | 不等於本輪親自重跑 |
| `本輪實測` | 在這次執行中實際跑過並留下結果 | 必須附可核對的測試命令／紀錄與條件 |
| `尚未重測` | 本次未重新執行舊測試 | 不會否定歷史測試的可信度 |
| `已核對` | 已對照指定檔案或事實範圍 | 不可籠統推成整個專案完成驗證 |
| `待確認` | 還沒有足夠資訊作最後結論 | 不等於否定或失敗 |
| `來源錨定` | 讓記憶能回到原始內容及其語境 | 保存來源不代表來源敘述為真 |
| `依賴前提` | 此主張受另一命題支撐或限制 | 前提變動要重審，不能直接判假 |
| `並存` | 同時間保留多個方案／解讀 | 不等於已合併，亦不等於等價 |
| `尚未取代` | 候選方案未替代原本方案 | 新方案的存在與優劣是另一問題 |
| `不能推出` | 由某些已知事實無法得到特定結論 | 不等於結論必為假 |
| `不只是` | 前述說法不足以概括重點 | 不能解讀為完全否定前述說法 |
| `取代` | 版本／判斷上的明確更替關係 | 舊來源仍須可追溯；不得物理刪除原文 |
| `引用` | 在指定語境使用已有語句／概念 | 跨版本時須保存原語義或明示重新解讀 |

初期不額外命名「已讀＋已做」「保存＋來源」「前提＋待決」等大量組合：直接用 `來源記載，……；尚未重測，……`、`原話，……；來源錨定，……`、`依賴前提，……；待確認，……` 比臨時暗號更能被穩定理解。需要時可以在**特定語境**定義複合詞，而不是任意更新所有領域的詞義。

## 舊字與新詞的對應（**僅用於理解 R01，非保證無損轉譯**）

| R01 單字 | R02 優先寫法 | 為何不是一對一自動替換 |
|---|---|---|
| `封` | `保留原話`／`保存原始記錄` | 保存原話與保存報告是不同來源類型 |
| `釘` | `來源錨定` | 有些舊釘只表示版本聲明，未驗來源內容 |
| `見` | `來源記載`／`已核對` | 看過資料和核對實際內容證據深度不同 |
| `跑` | `本輪實測` | 詞出現在句子裡不代表真有運行紀錄 |
| `候` | `待確認` | 候選方案、待證命題、待正式採用要分開 |
| `牽` | `依賴前提` | 依賴、相關、引用、受限不是同一關係 |
| `換` | `取代`／`重新映射`／`版本切換` | 詞義變動、編碼變動、正式採用不同 |
| `沿` | `繼承上層語境` | 多個可用上層語境時仍有歧義 |
| `否` | `否定`／`不能推出` | 否定命題與缺乏推論依據不同 |
| `不足` | `不只是`／`尚不充分` | `不只是`可能是論述焦點，不是技術不充分 |

## AI 自行解析的範圍與限度

AI 先看詞與語境，按自然語意推論組合；遇到兩種真正影響研究判斷的讀法時，回報歧義而不是編造詞典定案。若使用者未授權不得公開，文中即使寫「正式」「發布」也不產生權限；即使寫「已實測」，也須找得到真實紀錄。程式只用來索引、核對檔案、比對來源版本和評估成本；不能以 `Python parser PASS` 作為理解成功證據。
