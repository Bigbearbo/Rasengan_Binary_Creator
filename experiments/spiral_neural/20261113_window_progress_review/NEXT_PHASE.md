# 下一階段課程設計：先補齊 F2，再增加回覆詞數

2026-11-13，視窗GPT 提案 A。父模型固定 PR #28 `5ceec0c42507bb5646dc0d87089f4a86e0e6269c`；本文件未啟動神經訓練。F2 唯讀結果為三學生 0/900、0/900、1/900，先前 E1/E2/F1 全部重現，因此新增 F2 的教學有明確待解問題。

## 1. 研究問題與最小改動

問題：三個已會回音一詞、回音兩詞、翻轉一詞的學生，能否再學會翻轉兩詞，同時恢復並保有既有能力？本輪只回答持續學習的可行性與代價，沒有預設要證明這套課程優於所有其他教法。

沿用同 900 個四詞 payload、原五資訊位＋尾零、39-bit Q、L80/H64、10,499 參數、原 P030 Adam .003、逐 target 生效更新、全域 target 洗牌。資料不換、模型不重開、詞寬不變、沒有新增位置特徵或學生側解析器。

新候選 profile `SLE-AEM2-n5-v1` 只增加 `op100,r2`：前兩詞各反五資訊位，尾零仍為 0；舊 E1/E2/F1 的 Q/A 必須逐 byte 相同。普通輸入詞 ID0..29；輸出 30/31 的六位外形是字面答案，不能解釋成 END/UP。`S` 才是外部停止。其後 E3/E4 沿用 Echo010 語義。

## 2. 第一階：F2 混教

父 state 使用各 seed 的 PR #28 `science/seed*/final-state.npz` 原 bytes，state hash 見本目錄凍結 probe protocol。保留 p/m/v/birth/t/RNG 和原成本計數器；新成本用差額。checkpoint 中原 t 分別 297000、400500、441900，不能歸零或套用其他 seed 的動量。

每個 payload 各出 E1、E2、F1、F2 一題。依 pair_id、上述類別順序、答案位置（含 S）建立 canonical target pool，以 `default_rng(seed+555000)` 預先生成 40 輪排列並凍結實際陣列。這是新的課序，不覆寫 PR #28 的 seed+444000 課序。

| 類別 | Q 數／輪 | 每題 target（含 S） | 更新數／輪 |
| --- | ---: | ---: | ---: |
| E1 | 900 | 7 | 6300 |
| E2 | 900 | 13 | 11700 |
| F1 | 900 | 7 | 6300 |
| F2 | 900 | 13 | 11700 |
| 合計 | 3600 | — | 36000 |

長答案獲得較多 target 更新是此沿用政策的一部分；不能宣稱四類 loss 等權。先不加入另一個加權或批次 Adam 變因。

訓練前驗全部三模型的舊三類各 900/900。新 F2 基線可讀本輪已公開輸出，程式接線變動時才重新做必要核對；不必為每個流程文件反覆跑一整套稽核。若舊能力無法重現，先停止並修復載入／介面問題，不重新初始化學生來掩蓋差異。

每輪後做四類完整自由生成，沿用 cap32、L80 上限，由模型自己的輸出決定下一個輸入。四類各 900/900 連續兩輪才完成；任何一類失敗清零連勝。每學生最多 40 輪，不在看到結果後延長、改 seed、改課序或挑最佳 checkpoint。可保留失敗軌跡另立下一版，不把研究失敗當成不可修改的禁令。

每輪需要整題正確率、每個輸出詞、STOP、首錯位置、上輪正確→本輪錯誤及恢復數。首詞也可能失敗，不能只看新增第二詞；總分相同也可能是不同題互相交換對錯。

每輪 train MAC 為 758,016,000；40 輪上限每學生 1,440,000 更新／30,320,640,000 train MAC，三學生上限 4,320,000 更新／90,961,920,000 train MAC。這是最壞矩陣乘加預算，不是預估實際耗時。probe、I/O、必要驗證另外計，不能與訓練混成同一個成本數字。

科學輸出保存每輪最終完整 state、逐題實際輸出、target trace digest、成本及停止決策。沿用已驗過的 learner 不需要重做全部工程梯度測試；對新 Q/A、target pool、父狀態承接與新增停止決策做有界驗證即可。正式執行者先凍結 manifest 和實際課序；這份工作單供 Codex 接棒，本輪沒有啟動下一階段訓練。

## 3. 第二、三階：E3，然後 E4

F2 完成後，從各自終態增加 E3，保留 E1/E2/F1/F2。再完成後增加 E4，保留五舊類。每一步只新增一種答案長度；這兩步是候選後續，須各自凍結實際輸入與課序，尚未實作或訓練。

| 階段 | 類別 | 同 bank 題數／輪 | targets／輪 | 最長正確上下文 | 每輪 train MAC |
| --- | --- | ---: | ---: | ---: | ---: |
| F2 | E1,E2,F1,F2 | 3600 | 36000 | 51 | 758016000 |
| E3 | 加 E3 | 4500 | 53100 | 57 | 1118073600 |
| E4 | 再加 E4 | 5400 | 75600 | 63 | 1591833600 |

四詞完整回音需 24 bits 加一個 S，共 25 動作，原 cap32 與 L80 已容納，不需在此同時擴網。E3/E4 在原 900 payload 上學會仍是固定 bank 掌握；新輸出三詞／四詞組合空間分別可達 30^3／30^4，不能把 900 題改稱全域。

有需要時才加入獨立的新組合診斷：例如 E3 學會後保留 `(a,b,d)`，把第三詞改為 `(c+δ) mod30`，δ 事前固定為 1、7、13。這改動答案相關詞，每組前兩詞對應的三種新三詞答案未在原固定 bank 直接受教，比只換無關第四詞更能檢驗新組合。另改 d 才是無關後綴穩定性。兩類分開報，不能用其分數選 checkpoint 或臨時補訓，也不把這項診斷設為繼續教 E4 的必要門檻。

## 4. 長期成長與失敗後怎麼選

先保留模型的既有協調，再讓訓練處理新能力。本輪不手工改權重、硬接 copy/flip 電路或讓外部解析器替學生算答案。這是本方案的控制方式，不是把手工權重構造研究一律判為無效；不同問題另立對照即可。

如果 F2 在預算內失敗，先按現有完整軌跡分清：已教也學不穩、舊題失去後未恢復、主要是 STOP／長度問題，還是內容位轉換問題。只挑一個有證據的下一變因，不一次更換模型、學習率、資料和更新順序。另需新設計才能比較續訓相對從零重學的節省；目前不能宣稱已隔離這個效率收益。

目前窗口並非 E4 的瓶頸。若未來將協議上限延至 N5/r5，最大正確上下文為 75、輸出含 S 為 31，仍在 L80/cap32 內；N6/r6 則為 87 和 37，兩個上限都要調整。這只是候選格式的容量計算，現有 profile 尚未正式允許 N5/N6。真擴窗口時先驗舊 raw Q 的 logits／輸出保存，再教新格式；格式變長導致答案起點後移，其適應成本須另外測，不等同於網路陣列擴大成功。
