# Staged unfreezing of the old MAX comparator (prospective matching control)
Run pro_min_transfer_20261119_v1, 2026-11-19. This addendum was specified after the original three-arm preregistration and before viewing any new-task outcomes. It does not replace any registered arm.

From the identical starting point and with the same three seeds, decoder, handcrafted copy circuit, task switch, initialization, batches, surrogate gradient, Adam settings and 512 MIN updates as the joint condition in the main protocol, hold the 15 comparator parameters exactly fixed initially. At the end of each update check whether the two-parameter MIN adapter returns the opposite choice for both of the two possible signed old comparison bits. On the next update after the first such step, allow updates to the original comparator and continue the adapter optimizer without resetting it. Start comparator Adam from zero state at release. The gate uses only the known two input states and the known task relationship, not any validation, test or challenge label. If eligibility never occurs, keep it frozen. With the original convention when the logit equals zero, record the tie rule used.

Record release step, number of open comparator updates, step-resolved hard old and new accuracy on the fixed original splits, numeric output errors on all 16,384 ordered ideal pairs and on the in-range subset, minimum observed old validation score, and matched endpoints against always-frozen and always-joint arms. Inspect whether open-comparator training preserves exact old behavior after the adapter has learned its correct polarity. Expected direction is less old forgetting than always-joint; exact preservation is an open question. This is a test of a two-state release rule in a particularly favorable task chosen by the experimenter. No new recovery phase required for this arm. Report as a prospective supplementary control and account its additional optimizer updates separately.
