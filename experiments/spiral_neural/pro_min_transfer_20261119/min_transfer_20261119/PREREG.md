# MIN acquisition after exact MAX, version 1
Prospectively specified before reading any new-task accuracy and before optimizer updates. Parent: Bigbearbo/Rasengan_Binary_Creator PR 133, exact handfilled selector on PR130's frozen operand receiver. Local run id: pro_min_transfer_20261119_v1.

**Question.** Starting at exact handfilled MAX, can a small learned task-conditioned addition also choose MIN? If the shared comparator may move during acquisition, can old errors persist after new-task mastery, and are they recoverable? We supply a correct task switch and word-copy circuit. No SLE opcode for MAX or MIN is being learned. MIN and MAX on unequal numbers are complementary, making this a particularly favorable growth task. Growth here is externally chosen.

**Data.** Use PR133's original trained receiver weights for the three original seeds (101,202,303) and original n7 paired splits. Run the receiver or use and independently match its actual saved operand predictions. Train only on the source training split. Keep legacy validation, test, and disjoint challenge evaluation separate. Keep repeated opcode/order observations visible; evidence units on the challenge are unordered pairs. Use full ordered 128 x 128 ideal decoded interface separately, report both all inputs and the subset a+b<128. Distinguish pipeline and ideal-input claims. Numeric accuracy treats equal operands as correct for either choice. Use unequal rows only to supervise left/right selection.

**Mechanism and arms.** Take original comparator logit c (scaled to the same positive decision orientation throughout). For MAX, selector is sign(c), and a fixed handfilled multiplexer emits an input operand. For MIN, attach an independently initialized two-number adapter (a,b)=(1,0) with logit a*u+b, u the old comparator's signed hard decision (+1/-1). All expanded arms add exactly two numbers and expose the same fixed task switch. (1) Frozen comparator, train a,b. (2) Joint, train a,b and all 15 comparator numbers. (3) Direct/overwrite negative control, train only the old comparator on MIN, use its same choice on both tasks. The direct control has no task switch and cannot express both answers on unequal pairs; it is an explanatory control, not a fair architectural competitor. Handfilled perfect choice with polarity (a,b)=(-1,0) is an analytic reference. Each paired seed uses identical batches across arms.

**Optimization.** Comparator coefficients are in units of 1/64 of an operand, with the starting tie offset inherited from PR133; sign orientation drawn from the saved source code. For expanded arms use binary cross entropy with logits a*u+b. For the joint comparator use a straight-through derivative of softsign(4c), namely 4/(1+abs(4c))^2, evaluated behind the hard sign; document the effect of the surrogate. Direct uses binary cross entropy with comparator logit. Separate fresh Adam optimizers, step size 0.02 for adapter numbers and comparator numbers, beta1=.9, beta2=.999, epsilon=1e-8; batch 64 unequal training rows with replacement, 512 MIN-only steps. Fixed evaluation steps 0,1,4,16,32,64,128,256,512. No tuning or stopping on validation, test, challenge, or ideal stress. Capture per-checkpoint accuracy, baseline-to-checkpoint changed old outputs, first measured 95% new validation, minimum old retention and final old/new accuracy.

**Recovery and attribution.** After step 512 intervene by replacing only the comparator by its initial weights with the learned adapter intact; measure old/new at once. Separately, from the unchanged step-512 state run 128 old-MAX-only batches at the same batch size and comparator learning rate with fresh Adam, holding the learned adapter fixed; evaluate at 1,4,16,32,64,128. Both joint and direct get the same old batches. Frozen has no trainable path for MAX, so carry it as a zero-update reference. Do not count a changed tie side as a wrong result. New-task reversals and shared-comparator drift are distinct metrics. Three paired receiver seeds are descriptive; do not treat repeated cases as independent seeds or generalize to natural-language acquisition.

**Audit and reporting.** Save data/split identities, source references, training batches or deterministic reconstruction inputs, all weights at registered checkpoints, full hard predictions (including all failures), metrics and code. Replay from the package to verify outputs; cross-check exact-step-zero and comparator intervention identities. Label unexpected runtime failures/amendments. Account for all trained updates, inference costs, successful and unsuccessful runs, and constant/learned parameters. Use U for the user premise, F for borrowed data/design, T for measured findings, A for interpretation.
