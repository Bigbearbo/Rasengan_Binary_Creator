# 舊答案節點與緊湊附帶位元的同歷史 VM 成本重播

日期：2026-11-02（Asia/Taipei）。實作與實測屬本輪新成果；前一版的 `tree_compact_cost_validation.md` 只有同歷史記憶布局算式，尚未實際重播比較兩套流程。

## 新增內容

新增 `tests/test_tree_compact_differential_cost.cpp`，Makefile 目標 `tree-compact-differential-cost-test`；本報告及 `results/tree_compact_differential_cost_run.log`。程式核心 ISA、舊答案節點、緊湊記憶樹及世界策略未改。測試用兩個 VM 個體分別裝載舊式「答案節點」與新式「題目節點＋附帶位元」；兩者使用一致的 VM 參數（`tree_capacity=31`、`program_start=1100`、`tree_start=300`、`step_limit=4000`）。

## 同條件設計

以一隻倉鼠連續執行 `[題目1, 題目2, 題目1, 題目2, 題目1, 題目2]` 六次題目階段；題目1的正解6，題目2的正解3。每階段從該題的記憶出發，重複選擇未試過的答案，將錯誤或正確結果寫回；答對後結束當前階段。後四階段為已掌握題的重複練習。逐次檢查兩種模型選出的答案完全一致，且正確標記完全一致；若不一致則失敗。測量每個 VM 語詞程式的 `executed_steps`、呼叫次數、峰值步數；按選擇、讀取與寫入三種工作分類記帳。使用同一試答歷史、相同題目、相同回饋；不同的是已實作的兩套資料布局和客體程式，並非逐條同一個 VM 程式。

## 解讀限制

1. 數據是「目前兩套實作」的端到端 VM 指令成本，而不是精心優化後的抽象資料結構比較；舊式查單一答案旗標，緊湊式需動態找題目 ID 並讀12位附帶記憶，實際工作流並非每條指令相同。VM 步數含宿主啟動的查詢與驗證，不能宣稱全數為個體自主思考負擔。沒有比較牆鐘時間。
2. 題目與選項為已知固定3位／八選一模型；一般長題目、更多選項與跨代繁殖生態尚未做對照。兩種布局仍有相同的24,000位 VM 總配置，表中的「預留」只指樹欄與緊湊附帶資料的邏輯保留位，不等於程序實際配置的整體 RAM。
3. 緊湊方案尚額外使用每個體五位查詢暫存，未列在表中已使用資料量；程式碼空間／宿主狀態也未列。舊式樹列9位包含答案節點的動作位；緊湊式每個題目樹列9位，另配12位附帶資料。
4. 原世界與緊湊世界的四倉鼠、題目升階與資源節奏並不相同，因此本輪特意建立獨立受控重播，**不得**將這次單倉鼠受控歷史的步數當成原來四倉鼠世界總步數。

[更新] 對同一歷史做 VM 實際重播後，現行緊湊布局確實減少已使用位元，但執行時的位址搜尋、附帶讀寫顯著增加步數。[取代] 只有同歷史數學布局換算，缺少同條件實測的狀態。[原因] 新的兩版差分程式已在同題目、同回饋序列下完成並以 sanitizer 通過。[狀態] 高（本輪可重現單倉鼠試驗）；推廣到大族群及優化後效能仍未知。

下一步可先減少緊湊方案重複的 `node()` 查找和一次讀完12位的成本，並保持客體 VM 真正操作記憶的原則；後續再比較不同容量、題目寬度與長期生存成本。不要急著進入壓縮語義或因為效率比較不利就退回「每答案一節點」的唯一方案。
