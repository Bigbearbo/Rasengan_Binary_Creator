# 緊湊記憶成本計數

2026-11-01。更動：`src/tree_compact_world.cpp`、`tests/test_tree_compact_world.cpp`、`README.md`，新增本報告、`results/tree_compact_cost_run.log`、`results/conversation_20261101_cost.md`。

容量31、四隻、兩題、11輪：260次 VM 程式呼叫、32189個執行步數，單次最多598步（每次上限4000）。實際題目節點8個，按每節點9位樹列與12位附帶資料，使用168位；四隻總預留31×(9+12)×4=2604位，其中樹1116位、附帶1488位。五位暫存清除工作區及其他 VM 配置不包含在168位內。容量1的四隻共4節點，預留樹36位、附帶48位。

比較同樣四隻各存兩題、共32個曾嘗試選項的假設歷史：原每個答案另占一節點，需(8題根+32答案)×9=360位樹列，答案的3位 action 共96位，合計456位；緊湊模型是168位，另有每個體五位查詢暫存及程式碼。這只是相同歷史的資料布局算式，並非原世界實測；原世界有不同補題流程，不能直接拿兩個模擬的實際值當同條件性能比較。緊湊方案在滿額預留容量反而較大（每節點21位），優點是錯答數不再吃題目節點。VM步數含宿主發起的查詢與驗證，不代表純個體運算；答對反覆領取+100淨資源仍按目前世界規則存在。
